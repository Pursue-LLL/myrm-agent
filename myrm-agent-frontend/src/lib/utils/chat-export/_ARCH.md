# lib/utils/chat-export/

会话导出域子包：多格式导出排版、批量 zip 编排、离线 HTML 渲染与样式模板。**无** React 组件，全部纯函数与构建器。

对外唯一门面为 `index.ts` barrel（`@/lib/utils/chat-export`）；组件层消费点一律经 barrel 取公开符号，不深路径引用内部构件。

`__tests__/` 覆盖导出排版（会话级在 `chatExport.test.ts`，含 `getExportLang`；单条消息各格式的下载在 `chatExportMessage.test.ts`）、HTML 构建与批量编排行为，另有十五组专项：`exportUrlPolicy.test.ts` 逐个钉住放行与拒绝的链接目标，`chatExportHtmlHostile.test.ts` 用恶意 Markdown 与恶意来源链接验证导出文件里没有能执行脚本的链接，`chatExportHtmlContrast.test.ts` 从样式表解析出两套主题的颜色并校验每一组文字与底色的对比度 ≥ 4.5，`chatExportHtmlMath.test.ts` 验证价格句不被配成公式、三种写法都渲染成公式、代码里的 `$` 与 `%` 原样、`\href` / `\includegraphics` 不产生链接或图片，`katexExportStyle.test.ts` 用安装的 KaTeX 样式表与字体验证内联结果（字体嵌入且逐字节一致、取不到的字体被丢弃、只缓存完整结果、并发共享一次抓取），`chatExportHtmlKatexStyle.test.ts` 钉住只有含公式的导出才带 KaTeX 样式、页面字号以 `rem` 为根，`printHtmlDocument.test.ts` 验证打印等字体就绪、等待有上限且 iframe 事后移除，`printChat.test.ts` 钉住打印的是按所选主题与语言构建的文档，`chatExportDocx.test.ts` 把真实转换出的 .docx 读回来逐项断言 Word 读到的内容（标题样式、各列表独立编号、表格与对齐、单元格内换行、代码样式、任务复选框、原生脚注（同一脚注引用两次得到两个）且无回链箭头、公式只出现一次（块级公式是独占一个段落的原生公式）且价格与代码里的 `$` 原样、只保留 http(s) / mailto / tel 链接、原始 HTML 不进文件、XML 非法字符不进文件、作者为 Myrm），`chatExportDocxImages.test.ts` 用真实的小图读回哪些图片被嵌入（PNG / JPEG / GIF / BMP 嵌入，WebP 与伪装成图片的网页退回文字，分片到达的图片按序拼回），`chatExportDocxImageLimits.test.ts` 钉住单张与总量上限（正在下载的图片也计入总量，被取消或不是图片的下载归还额度）、声明超限的图不下载、未声明或谎报大小的无限流在超限处取消、超时、并行抓取，`downloadMessageAsDocx.test.ts` 从一条消息走完整条链路（默认脱敏、思考链按需且以调用方给的标签与缩进块和回答分开、每条来源独占一行并带链接），`downloadMessageAsHtml.test.ts` 用真实的页面构建管线走完同一条链路并读回页面（页面语言与主题；思考链按需且以调用方给的标签放进引用块，与回答分开；每条来源独占一行并带链接），`messageFileName.test.ts` 对 Markdown / HTML / Word / 图片四种单条导出逐一钉住文件名（开启脱敏时不含凭据，含跨过 80 字符截断点的凭据；不脱敏时保持原文；去掉标题 / 引用 / 列表的行首标记；首行为空或只有标记符时回退为 `message`；按字符而不是 UTF-16 单元截断，截断点上的 emoji 保持完整），`chatExportMessageText.test.ts` 钉住思考链的两种排版（折叠的 `<details>` 与带标签的引用块，默认折叠）、不包含时不出现、脱敏先于排版、标签与来源段落的措辞取自调用方（来源按地址、标题、占位词的顺序取名，没有来源时不出现来源段落）；`docxTestKit.ts` 是它们共用的 .docx 读回工具，`docxImageTestKit.ts` 是两个图片测试共用的图片夹具与 fetch 桩（均为包内测试私有）。

- `index.ts`：域门面 barrel — 显式导出清单聚合 `chatExport.ts` 与 `batchExport.ts` 公开符号，组件层统一导入入口；新增导出须同步本清单（漏加即 typecheck 断裂，编译器护栏）。
- `chatExport.ts`：导出数据模型与多格式排版 — ExportMessage/ExportChat/ExportData 类型、Markdown/JSON 格式化、敏感凭据脱敏过滤、思考链/工具细节包含控制、单条消息导出（Markdown/Docx/Html/Image，CWE-312 脱敏防护；文本与文件名来自 `chatExportMessageText.ts`，前三种的「思考过程」「来源」标签由调用方经 `MessageLabels` 传入，所以文件用界面的语言写成；Docx 经惰性动态 import 调用 `chatExportDocx.ts`）、会话级 Markdown（通篇英文的固定格式，思考链标签为 `Reasoning`）、剪贴板写入、打印（经 `printHtmlDocument.ts`）与客户端自适应下载触发；HTML 文档构建经惰性动态 import 调用 `chatExportHtml.ts`；`getExportLang` 给出 HTML / 打印页面措辞的语言：取自应用语言（与界面同一套 `NEXT_LOCALE` cookie 解析与缺省回退，不取浏览器语言），页面只有中英两套措辞，繁体中文读中文套，其余语言读英文套。
- `chatExportMessageText.ts`：单条消息导出的文本 — Markdown 排版与文件名标题的纯函数，各格式的单条导出共用同一份。思考链有两种排版：Markdown 折进 `<details>`；HTML 与 Word 都由 Markdown 构建，且都会丢掉其中的原始 HTML，折叠块会让推理文字连标签一起消失、不带任何标记地排在回答前面，所以这两种用带标签的引用块（会话级 Markdown 复用同一个 `formatReasoning`）；凭据先脱敏再排版；来源列表用硬换行连接，每条来源在任何渲染里都独占一行；本模块不含任何语言：思考链标签、来源段落标题与没有地址也没有标题的来源的占位词都由调用方经 `MessageLabels` 传入（`ExportMenu` 取自界面翻译），来源按地址、标题、占位词的顺序取名；文件名取自文件里同一份文本的首行：开启脱敏时先整行脱敏再截断，去掉标题 / 引用 / 列表的行首标记（只有标记符的首行回退为 `message`），按字符截断到 80 个，截断点上的 emoji 保持完整；包内私有，由 `chatExport.ts` 调用。
- `batchExport.ts`：批量导出编排器 — 3 并发 + 1 次重试调用 `services/chat::exportChat`，markdown/json/html 三格式内容构建（html 走惰性动态 import `chatExportHtml.ts`），按日期归档目录与重名消歧，DEFLATE zip 打包，进度/取消回调。
- `chatExportHtml.ts`：Markdown-to-HTML 导出渲染器 — Rehype AST 安全渲染（默认全转义 + 细粒度放行）、代码高亮、iframe 挂件、自包含代码块一键复制交互，导出文档 100% 零原生 Emoji 自包含渲染；管线最后一步 `rehypeSafeLinks` 与来源列表都经 `exportUrlPolicy.ts` 判定链接目标；公式经 `../markdownMath` 渲染（`mathPlugins`，KaTeX 保持默认值），含公式的导出另由 `katexExportStyle.ts` 内联 KaTeX 样式表与字体（没有公式的导出不付这份体积）。
- `chatExportDocx.ts`：单条消息转 Word 文件 — Markdown 经 remark（GFM、`../markdownMath` 的 `mathPlugins` 与预处理，哪些 `$` 是公式与聊天里一致）与 rehype 得到 HTML，再由 `docx/html` 写成 Word 原生结构：标题样式、各自从 1 编号的列表、带对齐的表格、任务列表复选框、原生脚注（回链箭头去掉；同一脚注被引用几次就写成几个原生脚注，注文随之重复，编号由 Word 按出现顺序重排）、由 KaTeX 的 MathML 转成的原生公式（块级公式是独占一个段落的 `m:oMath`，库不生成 `m:oMathPara`）；`<br>` 在段落与表格单元格里转成换行（原始 HTML 其余部分不解析）；代码块与行内代码用文件自己定义的 `CodeBlock` / `InlineCode` 样式；链接只留 http(s) / mailto / tel 且须过 `exportUrlPolicy.ts::isSafeLinkUrl`（独立的 .docx 没有基准地址，相对地址、页内锚点与 `//host` 没有可用目标），其余只留文字，脚注引用是唯一放行的页内锚点；图片经 `chatExportDocxImages.ts`；作者与最后修改者为 Myrm；导出 Word 时才惰性下载 `docx` 与转换器，包内私有，由 `chatExport.ts::downloadMessageAsDocx` 调用。
- `chatExportDocxImages.ts`：Word 文件里的图片 — 转换器不下载图片，也会不作声地丢掉它读不了的图片，所以每张图先在这里抓取：按文件头（PNG / JPEG / GIF / BMP）而不是主机声明的类型判定，单张上限 10 MB（主机声明的大小超限就不下载；没有声明或声明不实的响应边读边计，超限就取消，不会把整个响应缓冲进内存）、一份文档合计 50 MB（正在下载的图片已收到的字节同样计入，被取消或不是图片的下载归还额度，所以它也是同一时刻内存里图片字节的上限）、每张最多等 10 s，所有图片并行抓取；抓不到、被 CORS 拒绝、超限或 Word 显示不了（WebP、SVG、伪装成图片的网页）的图退回 alt 文字，绝对地址的图变成指向它的链接，已在链接里的图只留文字；包内私有，限额可注入以便用小数据测试。
- `katexExportStyle.ts`：导出文件里的 KaTeX 样式 — 自己 `import 'katex/dist/katex.min.css'`（样式表随这个懒加载块一起装载，在没有聊天内容的页面上导出也取得到），运行时从 `document.styleSheets` 取 `.katex` 规则与 `KaTeX_*` 的 `@font-face`，把 woff2 抓成 data URI 内联，导出文件离线打开也能排版公式；取不到的字体被丢弃（回退系统字体）而不是让导出失败，只缓存完整结果，并发导出共享一次抓取；没有 `document` 或没有可读的 KaTeX 样式表时返回空串；包内私有。
- `printHtmlDocument.ts`：打印导出文档 — 隐藏 iframe 写入文档，等 `load`（上限 1.5 s）与 `document.fonts.ready`（上限 3 s；内嵌字体的解码晚于 `load`）之后调起 `print()`，iframe 3 s 后移除；包内私有，由 `chatExport.ts::printChat` 调用。
- `exportUrlPolicy.ts`：导出文件里的链接目标策略 — `isSafeLinkUrl` 只放行 `http` / `https` / `mailto` / `tel` 与无协议的相对地址（用浏览器同一套 URL 解析判定，tab、换行与前导控制字符的写法也不例外），`rehypeSafeLinks` 把被拒绝的链接变成不带 `href` 的纯文字，文字保留；导出文件在应用之外打开，能执行脚本的链接不能进入文件；包内私有。
- `chatExportHtmlTemplates.ts`：导出 HTML 组件与样式模板库 — 深浅双主题 CSS 变量（文字颜色一律取自变量，含成功色 `--ok`、失败色 `--danger`、徽标字色 `--on-accent`，两套主题下每组文字与底色的对比度 ≥ 4.5）、页面字号以 `rem` 为根（em 链若从浏览器默认字号起头，Chrome 会把低于最小逻辑字号的相对字号抬高，公式的上下标就被撑大；`rem` 根属于绝对字号，不受这项调整，仍跟随读者的默认字号）、Highlight.js 语法主题、离线响应式自适应布局、打印态样式隔离与暗黑模式白底强制反转、复制/主题切换交互脚本、多语言元数据统计标签；包内私有，外部消费经 `chatExportHtml.ts` 间接触达。

## 依赖

- `@/lib/utils/fileUtils`（POS: 通用文件工具）— 文件名清理与下载触发。
- `@/lib/utils/error-handling`（POS: 客户端轻量敏感凭据脱敏清洗工具）— 导出内容脱敏。
- `@/lib/utils/clipboardUtils`（POS: 剪贴板工具）— Markdown 复制写入。
- `@/lib/utils/locale`（POS: Locale 工具集）与 `@/i18n/config`（POS: 支持的语言与缺省语言）— `getExportLang` 解析界面语言。
- `@/services/chat`（POS: 聊天 API 请求层）— 单聊天导出数据源（`batchExport.ts` 批量编排消费）。
