# lib/instance-archive/

## 架构概述

整实例备份界面的纯逻辑（无 React 组件）：把后端的存储标识与错误码归并为用户语言，并决定如何重启。

## 文件清单

| 文件                        | 地位 | 职责                                                                                                                                                    | I/O/P |
| --------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| `format.ts`                 | 辅助 | `formatBytes` 字节数可读化、`formatBackupDate` 备份时间本地化                                                                                           | ✅    |
| `counts.ts`                 | 核心 | `COUNT_KEYS`（预览与恢复结果共用的计数键，必须与后端报告一致，由 server 架构测试钉住）、`losesHistory`（恢复后聊天/消息少于当前时为真）                 | ✅    |
| `reentry.ts`                | 核心 | `reentryGroups`：`config:` / `table:` / `path:` 标识 → 四类用户可理解的凭据分组，技术键名不外露                                                         | ✅    |
| `errors.ts`                 | 核心 | `archiveErrorMessageKey`：仅已本地化的稳定错误码（含自动备份的文件夹/写入/校验/不完整类）映射到文案键，其余回落到通用文案；换入失败码统一为「未能应用」 | ✅    |
| `restart.ts`                | 核心 | `planRestart` / `performRestart`：桌面端 Tauri 重启（非远程网关）、沙箱重建（请求不带 `reset_python_env`，用户已装的 Python 包保留）、裸进程由用户手动重启                                                       | ✅    |
| `__tests__/helpers.test.ts` | 测试 | 上述映射与重启方案的单元测试                                                                                                                            | ✅    |
