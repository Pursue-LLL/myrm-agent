# store/first-screen/ 模块架构

## 架构概述

桌面端冷启动时后端要几秒到十几秒才就绪，这段时间侧栏只有骨架。本模块把上次侧栏上的两个列表存在 WebView 的 `localStorage`，下次启动时先画出来，后端就绪、第一页数据到达后整体换成服务端的数据。它只改变「先显示什么」：后端何时就绪不变，依赖后端的请求仍然停在 [`lib/platform-readiness.ts`](../../lib/_ARCH.md) 的就绪门上，后端启动路径不受影响。

首次安装没有快照，没有任何提速；只有曾经成功加载过列表的安装才有。

### 存什么、什么时候用

- **白名单**：只存两个列表型首屏数据（`SnapshotSectionName`）——会话历史第一页（最多 20 条、归属于它加载时的项目筛选）和项目列表。会话行只存侧栏每行画出的内容：标题、标记、时间，以及最近消息的一行预览（截到 80 个字符，最宽的侧栏约显示 60 个）；预览必须存，否则带预览的行会在服务端数据到达时长高一行，整张列表在指针下跳动。新增一类数据要在这里登记并配编解码器。
- **只存后端确认过的数据**（`writer.ts`）：会话列表要带服务端分页信息（恢复出来的列表没有）、空闲、没有错误、没有按来源或关键词收窄；项目列表要已拉取完成。快照因此永远不会从上一份快照复制而来。
- **每次页面加载只提供一次**（`restore.ts`）：第一个来取的组件挂载拿到，之后不再提供；后端已就绪时不用。恢复的会话列表不带分页（不会在没确认的列表上翻页），项目列表的 `loaded` 仍为 false，组件照常发起读取，服务端的回答整体替换恢复的数据；会话列表刷新失败时保留恢复的列表，不弹错误面板。
- **失效**：存储信封带结构版本与构建标记（`NEXT_PUBLIC_APP_BUILD`，发布构建取 `RELEASE_TAG`，其余为 `dev`），不一致整体忽略；分区超过 14 天或时间在未来不用；任何读写异常都当作没有快照。
- **开关**（`gate.ts`）：`NEXT_PUBLIC_FIRST_SCREEN_SNAPSHOT` 取 `desktop`（默认，仅 Tauri 桌面运行时）/ `local`（任何本地模式，供浏览器里复现与测量）/ `off`。服务端渲染与远程网关生效时一律关闭，因为快照来自本机后端，不能套在远程服务上。
- **多窗口**：落盘时重新读取已存的信封，只替换本窗口写过的分区，两个窗口不会互相覆盖。同一个 1 秒窗口内的多次变化合并成一次写入（窗口从第一次变化算起，列表持续变动时也每秒落盘）；`pagehide` 与页面转入后台时立即落盘。

## 文件清单

| 文件                    | 职责                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------ |
| `gate.ts`               | 特性开关：此处是否使用快照                                                           |
| `envelope.ts`           | 存储层：版本化信封、分区过期、合并写入、按分区合并                                   |
| `chatHistorySection.ts` | 会话历史分区的编解码：白名单字段、一行预览截到 80 字符、最多 20 条、项目筛选键       |
| `projectsSection.ts`    | 项目列表分区的编解码                                                                 |
| `restore.ts`            | 恢复：把存下的列表放进 store（每页面加载一次，后端已就绪时不放）                     |
| `writer.ts`             | 写入：订阅会话与项目两个 store，只存确认过的数据，失败只记日志；由 `PageLayout` 启动 |

## 依赖

- `@/lib/deploy-mode` — 部署形态与远程网关判断
- `@/lib/platform-readiness` — 后端是否已就绪
- `@/store/useChatStore`、`@/store/useProjectStore` — 两个列表所在的 store
- `@/services/chat`、`@/services/projects` — 列表项类型
- 被 `components/features/sidebar/ChatHistoryList.tsx`（挂载时恢复并强制刷新）、`ProjectBar.tsx`（挂载时恢复并拉取）、`components/layout/PageLayout.tsx`（启动写入）使用

## 约束

- 不动后端启动路径，不放行任何依赖后端的操作；恢复的数据只用于绘制，替换它的永远是服务端的回答。
- 只存列表型首屏数据；消息只存侧栏每行本来就画出的那一行预览（≤80 字符），不存第一条消息、消息正文、凭据、配置或任何输入内容。
- 存快照失败（含数据异常）只记日志，不影响触发它的 store 更新；读到的存储内容一律不信任，形状不对的行丢弃。
- 恢复的列表不是确认数据：不带分页，不被写回。
