# hooks/voice/tts/

TTS 输出门面 [`../useTTS.ts`](../useTTS.ts) 的内部模块：浏览器 SpeechSynthesis 引擎、后端 API 引擎与两者共用的类型。门面是唯一对外入口，这里的模块只被它引用。

## 文件清单

| 文件               | 职责                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `types.ts`         | 播放状态 `TTSState`、引擎选择 `TTSMode`、引擎的控制面 `TTSEngine`、门面的入参 `UseTTSOptions` 与返回值 `UseTTSReturn`（引擎的控制面加 `toggle`）；`TTSMode` 由 `useTTS.ts` 重新导出                                                                                                                                                                                                                                                                             |
| `useBrowserTTS.ts` | 浏览器引擎：`window.speechSynthesis` 朗读去掉 markdown 的文本，`speak` 取代正在进行的朗读（去掉 markdown 后没有内容则不动朗读队列）；朗读队列是整页共享的，`stop` 与卸载只在实例持有当前那段话时才取消队列、事件也只在持有时才响应，所以没在朗读的消息行不会因停止、卸载或没有内容可读而打断别的行；浏览器不支持时所有控制都是空操作                                                                                                                            |
| `useApiTTS.ts`     | API 引擎：`/tts/synthesize-stream` 边收边播（MediaSource），浏览器的 MediaSource 不支持 MP3 时退回一次性取回的 `/tts/synthesize`；合成失败用 toast 提示（503 提示服务端未启用 Edge TTS，其余提示朗读失败）；停止时中止请求并释放音频与对象 URL；音频元素之间不排队，所以 API 引擎的实例之间一次只有一个在朗读：`speak` 在去掉 markdown 后有内容时先停掉正在朗读的实例（含它在途的合成请求，不论属于哪条消息行），卸载时让出这个位置；没有内容可读则不动别的实例 |

## 测试

`__tests__/` 每个引擎一份：`useBrowserTTS`（假的整页朗读队列上的归属：被别的行取代、自己替换后旧那段话迟到的中断回报、`stop`、朗读中的行卸载，以及没在朗读的行停止、卸载、没有内容可读都不打断别的行）、`useApiTTS`（假的音频元素与合成请求上的互斥：朗读中被别的行接管、合成中被接管时请求被中止且迟到的应答不出声、同一行重复朗读、没有内容可读的行不打断别的行、被接管的行能接管回来、被取代的行卸载后仍能停掉当前朗读、朗读的行自己播完后别的行照常接管）。门面的用例在 [`../__tests__/useTTS.test.ts`](../__tests__/useTTS.test.ts)。

## 依赖

- 父模块 [`../_ARCH.md`](../_ARCH.md)

## 约束

- 只被 `../useTTS.ts` 引用；域外消费者经 `@/hooks/voice/useTTS` 取 `useTTS` 与 `TTSMode`，不直接引用本目录
- 共享类型独立成 `types.ts`：引擎文件不能反向 import 门面（`import/no-cycle`）
- 门面每次渲染都调用两个引擎 hook（hook 顺序固定），按 `mode` 取其中一个；引擎只提供 `speak` / `pause` / `resume` / `stop`，`toggle` 由门面按该引擎的状态统一提供
