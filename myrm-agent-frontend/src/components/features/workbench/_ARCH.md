# Auxiliary Workbench Component Architecture

## 1. 概述与定位

本模块位于 `myrm-agent-frontend/src/components/features/workbench/`，为当前会话的工作区提供辅助工作台：

1. **右侧/底部双轴独立停靠抽屉 (`MultiTabWorkbench`)**：支持水平调宽（320px ~ 960px）与垂直调高（200px ~ 640px），双轴灵活停靠；没有当前会话时显示引导提示；切换会话时清空终端历史并让两个页签按新会话重新挂载；切到终端页签时文件页只隐藏不卸载，回来时已展开的文件夹、搜索词和打开的预览（含未保存的编辑）原样还在；
2. **会话工作区文件页 (`tabs/WorkbenchFiles`)**：目录树（深层文件夹展开时按需加载）、实时刷新、文件预览与编辑、上传/重命名/移动/删除全部复用 [`workspace-browser/`](../workspace-browser/_ARCH.md)，与侧栏工作区视图同一份实现；文件名搜索由服务端遍历整个工作区，结果盖在目录树上，预览再盖在最上层，关闭后逐层回到结果或目录树；预览里未保存的文字留在内存草稿里，关闭抽屉不询问，再次打开时文件页重新打开最近编辑的那个文件（见下文「关闭抽屉不丢未保存的编辑」）；
3. **会话工作区终端面板 (`tabs/WorkbenchTerminal`)**：在会话工作区内执行命令、终端历史记录；一键把某条命令与输出（过长只留末尾 8000 字符并注明前面已省略）追加到聊天输入框，不覆盖用户已输入的内容；请求失败（被安全闸拦截、没有工作区、超时、其他）以用户语言写进历史，退出码留空并显示「失败」，不透出服务端原文；
4. **工具菜单入口 (`WorkbenchToggleTrigger`)**：导航栏「工具」菜单唤起，保留快捷键 `Cmd+Shift+B` / `Ctrl+Shift+B` 与全局事件 `myrm:open-workbench`；`showTrigger={false}` 时只保留监听。网页版里这个组合先被 `hooks/shell/useGlobalShortcuts` 当作浏览器面板快捷键截获（捕获阶段并终止事件），到不了这里；Tauri 下那边的快捷键不带 Shift，没有冲突。

## 2. 模块结构与文件表

| 文件                             | 职责                                                                                                                  |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `MultiTabWorkbench.tsx`          | 工作台主外壳容器，包含 Tab 切换（文件页隐藏保留，切走时暂停其中播放的音视频）、拖拽手柄尺寸调节、停靠位置转换与无障碍 |
| `WorkbenchToggleTrigger.tsx`     | 工具菜单入口与全局快捷键调度器（`showTrigger` 控制是否渲染入口）                                                      |
| `tabs/WorkbenchFiles.tsx`        | 会话工作区文件页：复用 `workspace-browser` 的目录树与预览，搜索结果盖在目录树上；挂载时若本工作区有保留的未保存文字，重新打开最近编辑的文件并提示已恢复 |
| `tabs/useWorkspaceFileSearch.ts` | 文件页的防抖整库文件名搜索（只采纳最新一次查询）                                                                      |
| `tabs/WorkbenchTerminal.tsx`     | 会话工作区终端控制台、命令执行与追加到聊天输入框                                                                      |
| `tabs/terminalOutput.ts`         | 终端纯函数：注入片段（自适应围栏、尾部截断）、追加到输入框、请求失败分类                                              |
| `index.ts`                       | 门面导出入口                                                                                                          |
| `__tests__/`                     | 组件单元测试套件                                                                                                      |

## 3. 设计红线与质量约束

- **Escape 先给最内层**：抽屉在 `window` 监听 Escape；文本输入框（搜索、重命名、终端输入、文件编辑器）里按下的、以及已被右键菜单/对话框处理的 Escape 不会关闭抽屉，免得取消一次输入或编辑就把整个抽屉关掉；
- **异步回写守卫**：命令输出回写前，用 `useWorkbenchStore.sessionEpoch`（每次切换会话递增）核对，上一个会话的迟到响应一律丢弃，不会串到新会话的界面；
- **抽屉不得成为 fixed 的包含块**：`MultiTabWorkbench` 外壳不加 `backdrop-filter` / `transform`，否则文件浏览器按视口定位的右键菜单与确认对话框会错位；
- **文件页不自带读文件逻辑**：文件树、预览、写操作全部来自 `workspace-browser`，工作台只加搜索与布局；目录树只加载有限层数，所以搜索交给服务端按整个工作区查找，不在已加载的树上过滤；加载、搜索与文件读不出来时都只显示本地化提示，不透出服务端原文；
- **文件页保持挂载**：终端页签只用 `hidden` 隐藏文件页而不卸载它，文件页自己的状态（展开的文件夹、搜索词、预览与编辑）切页不丢；隐藏时暂停其中的 `video` / `audio`；终端页签仍按需挂载（历史在 store 里）；换会话时两个页签都重新挂载；
- **关闭抽屉不丢未保存的编辑**：编辑器把与文件不同的文字同步留在 `useWorkspaceDraftStore`（按工作区与路径），所以关闭按钮、Escape、快捷键、悬浮入口与工具菜单都不必询问，抽屉也没有任何关闭拦截；再次打开抽屉，文件页挂载时若本工作区有保留的文字，就重新打开最近编辑的那个文件并提示已恢复，文件已变化则直接给出冲突提示；切换会话同样不丢，回到该工作区时接回。只有离开预览或退出编辑时，才用应用内对话框（`chooseAction`）问保存 / 放弃 / 留下。草稿只在内存：存在未保存文字期间页面登记 `beforeunload`，网页版关闭或刷新前由浏览器询问，刷新后即丢，桌面端彻底退出应用时同样丢失；
- **零 any**：所有状态和组件属性必须使用具体 Type Hints；
- **行数控制**：单文件严格控制在 350 行以内，单一职责；
- **零原生 emoji**：图标全量使用标准 SVG 矢量组件；
- **无障碍访问**：满足 `role="complementary"`、`role="tablist"` / `role="tab"`（`aria-controls`）/ `role="tabpanel"`（`aria-labelledby`）与 `aria-label` 等 a11y 规范。
