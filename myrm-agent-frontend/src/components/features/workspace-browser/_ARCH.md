# workspace-browser/

## 架构概述

工作区内嵌浏览器预览与检查器联动。有两个使用方：侧栏工作区视图（`layout/ChatSidebarContent`）与辅助工作台的文件页（`workbench/tabs/WorkbenchFiles`），二者共用同一套目录树、实时刷新与预览。

## 文件清单

| `WorkspaceDialogs.tsx`      | 组件 | 工作区文件操作确认对话框（删除确认、移动目标）；Escape 只取消对话框本身                                                                                                                                                                                                                                                                                                                                                 |
| `WorkspaceFileBrowser.tsx`  | 核心 | 沙箱文件树浏览器：展开/收起、右键菜单与写操作入口；扫描进行中保留已有目录树（只有还没有任何内容时才显示转圈），扫描失败只显示本地化提示、不透出服务端原文；顶部名称把会话自己的工作区文件夹（`chat_<chatId>`）显示为用户语言的「本次对话的工作区」；未扫描到的文件夹（`children: null`）展开时经 `onLoadChildren` 加载，失败以本地化提示并收起；目录右键「AI 整理」或「设为项目根目录」→ 联动聊天与 Project Scoped 边界 |
| `WorkspaceFileTree.tsx`     | 组件 | 目录树行（递归）：文件夹箭头/加载中转圈、图标、大小、@ 引用（与行按钮并列的独立按钮）、行内重命名；只做展示，数据与操作全部来自属性                                                                                                                                                                                                                                                                                     |
| `WorkspaceContextMenu.tsx`  | 组件 | 右键菜单（重命名/移动/删除；目录另含 `onOrganize` 与 `onSetProjectRoot` 入口）；贴近点击位置并保持在视口内，点击任意处或 Escape 关闭                                                                                                                                                                                                                                                                                    |
| `WorkspaceFileOps.tsx`      | 组件 | 上传（拖放与按钮）、新建目录、行内重命名、`useWorkspaceFileOps` 状态                                                                                                                                                                                                                                                                                                                                                    |
| `WorkspaceFilePreview.tsx`  | 组件 | 选中文件内联预览；文本走代码编辑器与内嵌 Inline Diff 审查，编辑状态来自 `useWorkspaceTextEditor`，服务端判定不可编辑的文件显示只读提示且不出现编辑入口；富媒体委托 `RichMediaFilePreview`；有保留的未保存文字时以编辑态打开；关闭预览或退出编辑时若有未保存编辑，应用内对话框选保存 / 放弃 / 留下（文件已变则无保存）；Ctrl/Cmd+S 在预览所在面板被隐藏（工作台切到终端标签）时不响应；markdown / CSV 默认以渲染视图打开（超过 200 KB 或读取时被截断的文件只看源码），头部「预览 / 源码」开关切换，编辑始终在源码上；编辑在宽屏且指针精确的设备上用 Monaco（`WorkspaceCodeEditor`），触屏与窄屏用行号文本框（`LineNumberedEditor`），鼠标移到或聚焦「编辑」按钮时预取编辑器代码；文件读不出来只显示本地化提示      |
| `WorkspaceTextViews.tsx`    | 组件 | 文本预览的两种视图：只读行号代码 `LineNumberedCode`（每行一个块级行，行号由 CSS 计数器画在行首：换行的长行只占一个号，行号始终与该行第一行文字对齐，也不进入选区、复制与读屏；超过 2,000 行时加 `numbered-code-lazy`，浏览器跳过屏外行的布局，代价是滚动条长度在行被看过之前是估算值；超过 100,000 行退化为不带行号的纯文本；样式在 `app/numbered-code.css`，字号与行高由它统一设置，元素上不能再加字号工具类）与行号编辑器 `LineNumberedEditor`（不换行，行号与正文共用同一行高 `leading-5`，逐行对齐）；行号是一整块 `aria-hidden` 文本，编辑器的行号列另带一条始终为空的横向滚动槽，与文本框自己的横向滚动条同高：文本框有横向滚动条（有超出宽度的长行）时，滚到底行号与最后几行对齐；系统滚动条占位而文本框没有横向滚动条（全是短行）时，行号列比文本框矮一条滚动条的高度，滚到底最后一行行号会被裁掉一截（覆盖式滚动条不受影响）；编辑器的文本框以文件名作为可访问名称；另含文件大小格式化                                                                                                                                                                                                                                                                                |
| `WorkspaceCodeEditor.tsx`   | 组件 | 文本编辑的 Monaco 适配：文字归调用方（`useWorkspaceTextEditor`）持有，编辑器只是它的视图。编辑器里的每次改动经 `flushSync` 在 Monaco 事件返回前交给调用方（Monaco 的 onChange 不在 React 事件系统里，不同步则紧接着的 Ctrl+S、保存按钮或关闭会按屏幕上尚未提交的旧文字保存）；调用方给的文字与编辑器不同（载入最新、放弃、磁盘更新）时在布局副作用里用 `model.setValue` 换内容并保留光标与滚动位置、不回报为输入（包装组件的 `value` 属性是一次可撤销的整体替换，会让外部刷新变成用户可 Ctrl+Z 退回的一步），换内容后撤销历史重新开始；模型换行固定 LF（Windows 上 Monaco 默认 CRLF，一次什么都没改的保存就会改掉文件换行）；每个挂载的编辑器用 `inmemory://workspace/<序号>/<文件名>` 作模型路径，同名文件互不共用文字与历史，语言由文件名识别；主题取 `resolvedTheme`，底色见 `app/workspace-code-editor.css`；TypeScript / JavaScript 只留语法诊断（单个文件没有项目上下文，语义诊断全是噪声），关闭补全弹窗与 Unicode 高亮（中文标点不会被标黄）。键盘：Tab 在编辑器内是缩进，移出焦点用 Monaco 的「Tab 键移动焦点」开关（Windows / Linux 为 Ctrl+M，macOS 为 Ctrl+Shift+M，实测切换后 Tab 离开编辑器）；桌面端与窄屏互相切换时撤销历史不保留 |
| `codeEditorSupport.ts`      | 工具 | 代码编辑器用在哪：媒体查询 `(min-width: 769px) and (pointer: fine)`（768px 是应用里「手机」的既有分界），`useSupportsCodeEditor` 随窗口变化更新、服务端渲染与首帧前取 `false`，触屏从不下载编辑器；`preloadCodeEditor` 只在会用到编辑器的环境里预取其代码包。触屏与窄屏用文本框，是因为系统键盘、选择手柄与输入法由浏览器原生处理 |
| `WorkspaceTextNotices.tsx`  | 组件 | 文本上方的三类提示：只读原因（编码无法安全保存 / 混用换行方式 / 文件过大）、已恢复上次未保存的修改，以及保存冲突（另存为副本 / 放弃我的内容打开最新 / 用我的内容覆盖）；文案全部本地化，不透出服务端原文与技术术语                                                                                                                                                                                                      |
| `InlineWorkspaceDiff.tsx`   | 组件 | 工作区文件审查面板：文件名标题与关闭按钮，正文是磁盘上已存的版本与编辑中草稿的对比，对比交给共享的 `lib/diff/TextDiffViewer`（只列真正改动的行与前后各 3 行；改动大到来不及对比时只说明两侧行数）；整个面板自己滚动，不再套一个 300px 的内层滚动框 |
| `RichMediaFilePreview.tsx`  | 组件 | 富媒体（图片/音视频/PDF/Office/SVG）预览分发；`getPreviewKind` 扩展名路由 + `kind` prop 覆盖；图片禁用 artifact 编辑按钮                                                                                                                                                                                                                                                                                                |
| `RenderedTextPreview.tsx`   | 组件 | 文本文件的渲染视图：`getRenderedKind` 按扩展名认出 markdown / CSV（没有扩展名的文件和 `.md` 这类隐藏文件不算）；`RenderedTextPreview` 复用聊天工件的 `DocumentPreview` / `SpreadsheetPreview`（按需加载），markdown 里的相对图片与链接经 `resolveWorkspaceUrl` 指向工作区内的文件；`ViewSwitch` 是头部的「预览 / 源码」分段开关；`RENDER_BY_DEFAULT_MAX_BYTES`（200 KB）是默认渲染的体积上限（Chromium 实测 200 KB markdown 渲染约 1 秒、600 KB 约 2.5 秒） |
| `resolveWorkspaceUrl.ts`    | 工具 | 纯函数：文档里的相对地址（`./a.png`、`../b/c.md`、百分号编码、`?query` 与 `#fragment`、Windows 反斜杠）按文档所在目录解析成内容接口 URL；协议地址、`#锚点`、`//host`、以 `/` 开头的地址原样返回；`..` 不会越过路径根，是否走出工作区由服务端校验并拒绝 |
| `useEscapeDismiss.ts`       | Hook | 临时浮层（右键菜单、对话框）的 Escape 关闭：监听 `document` 并终止事件，宿主（如工作台抽屉监听 `window`）不会随之一起关闭                                                                                                                                                                                                                                                                                               |
| `useWorkspaceFileChanged.ts` | Hook | 工作区文件变化的节流回调：从一阵变化的第一个事件起 300 ms 后调用一次（不顺延，写入方一直写也不会饿死更新）；事件只说「工作区里有变化」，不比对工作区路径（服务端用它解析后的写法），由调用方检查自己的文件 |
| `useWorkspaceFiles.ts`      | Hook | 三部署 agent vault 文件树：首扫两层，更深的文件夹经 `loadChildren` 按需加载，每次刷新都会重读已打开的文件夹，刷新期间原目录树原地保留、新结果到达时整体替换，换工作区则立即清空；register watch + SSE auto refresh（经 useGlobalEvents）；较旧的扫描结果与切换工作区后才到的文件夹结果一律丢弃                                                                                                                          |
| `useWorkspaceTextEditor.ts` | Hook | 单个文件的文本编辑状态：带版本读取、草稿与由草稿对照文件内容得出的 `dirty`；保存始终基于读取时的版本，文件在磁盘上已变化时保留草稿并进入冲突态（载入最新 / 覆盖 / 另存副本）；保存期间新输入的文字仍算未保存，同一文件同时只有一次写入；未保存草稿同步保留到 `useWorkspaceDraftStore`，下次打开接回（`restored`），文件已变则直接进冲突态；文件打开期间保持最新：磁盘上变了，没输入过就直接换成新内容，输入过就保留输入并进入同一个冲突态；检查只带已持有的版本（未变化时几百字节），自己的保存不会被当成外部修改，写入进行中、超大无版本文件和读不到的文件都不检查；晚到的读取与保存结果不会作用到新文件，保存失败仍以本地化提示告知             |
| `__tests__/`                | 测试 | 组件与 Hook 的单元测试（jsdom）；`editorTestKit.ts` 是编辑器测试共用的读写桩与打开、输入助手，各测试文件仍各自声明 `vi.mock` |
