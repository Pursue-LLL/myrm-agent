# composer/

## 架构概述

聊天输入区 `MessageInput` 的组成单元。`MessageInput.tsx` 只做装配：持有各块之间必须共享的状态（编辑器是否全屏、光标位置、斜杠与 @ 面板、输入历史弹窗），把 `useMessageInput` 提供的输入状态接到本目录的单元上；展示、分流与副作用各归一个单元，单元之间不互相引用。

按职责分三类：

- **展示单元**：props 进、事件出。`ComposerTextarea`、`ComposerSendControls`、`ComposerDropOverlay`、`ComposerStatusIndicators`、`ComposerVoiceActions`、`MobileComposerEntry`、`MobileComposerSheet`、`CompactConfirmDialog`。
- **状态 Hook**：`useComposerPanels`（三块面板的开合联动）、`useComposerDragDrop`（三类拖放合并成一个出口）、`useCaretPosition`、`useHideChatWorkspacePicker`。
- **纯函数**：`composerKeyDown`，表单级按键分流，分流顺序即优先级。

桌面主行与选项区不在本目录，由 `../composer-options/` 承载；手机（<`sm`）两者都不显示，改由 `MobileComposerEntry` 的「+」打开 `MobileComposerSheet`。

## 数据契约与依赖

- `MessageInput` 的接线由 `../__tests__/MessageInput.{keyboard,controls,panels}.test.tsx` 守卫（子组件与重 Hook 换成记录属性的替身，见 `../__tests__/messageInputHarness.tsx`）；本目录各单元经它们间接覆盖，纯逻辑部分另有直接单测。
- `data-chat-input`（`ComposerTextarea` 的文本框）与 `data-chat-composer`（`MessageInput` 的输入容器）是外部按选择器找输入框的约定：`useComposerFastFocus`、`usePriorChatComposerDrop`、划词与引用工具条、搜索对话框、E2E 桥都依赖它们，预热取消也靠 `[data-chat-composer]` 判断焦点是否还在输入区内；改名要同步。
- 手机 / 桌面的分界是 Tailwind 的 `sm`（`min-width: 640px`），`useComposerPanels` 用同一断点决定能力编辑落点。
- 本目录不放选项区内的控件：新增选项进 `../composer-options/` 的选项区，手机上进 `MobileComposerSheet`。
