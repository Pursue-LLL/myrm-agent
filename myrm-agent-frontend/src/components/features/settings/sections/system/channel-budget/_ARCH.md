# settings/sections/system/channel-budget/

## 架构概述

渠道预算面板（用量统计页的一块）：每个聊天渠道一张卡片，设置每日花费上限、启停、查看近 7 个预算日各发送者的花费。`ChannelBudgetSection` 是入口，把数据源（三个 hook）、渠道卡片、新增表单与删除确认组合起来。新增渠道时，渠道键从服务端已有对话的群聊里点选，也可以手输。上级：[../_ARCH.md](../_ARCH.md)。

面板有四条贯穿各文件的规则：

- **每次编辑只发它改的那一个字段（PATCH）**，写入之后读回整张列表，写入被拒时同样读回（被拒往往说明屏幕上的列表已经过时，比如渠道已在别处被删）；所以连着做的两次编辑、或另一个页面同时做的编辑不会把对方的值写回去。新增渠道例外，整条创建（PUT）。
- **服务器回答之前不下结论**：首次加载是占位骨架，加载失败是带「重试」的提示（屏幕上已有的列表保留，提示说明它可能不是最新），只有加载成功且为空才显示空态文案；候选群聊同理，回答之前、查询失败时不显示候选区，回答为空才说明没有可选的群聊。同时在途的请求里，只有不早于屏幕上那次结果的请求才能改变屏幕。
- **服务端会拒绝的操作先在界面说明**：区间外的上限不发出，用户的语言给出区间；删除渠道会撤掉它的守卫（没有策略就不受限），所以垃圾桶按钮只发起确认，确认之后删除。
- **渠道键只由服务端给出规范形式**：候选群聊是服务端存对话时用的键，界面不自己推导或比较键的写法（服务端对不同通道的 ID 有不同的规范化），也不显示群名（有的通道不提供可靠的群名）；手输的键若还没有任何对话落在它名下，卡片用中性文字提示，不当作错误。

## 文件清单

| 文件 | 职责 |
|------|------|
| `ChannelBudgetSection.tsx` | 面板入口：组合列表加载的三态（骨架 / 失败提示 / 空态）、渠道卡片、新增表单与删除确认（共享 `ConfirmDialog`，描述里写渠道名；渠道留到对话框淡出之后，文字不在淡出时变化）；写入（更新 / 创建 / 删除）统一经 `settle`：无论成功还是被拒都读回列表，被拒时 `apiRequest` 已弹出提示；点「添加」时才请求候选群聊，已有渠道的群不再作为候选 |
| `useChannelBudgets.ts` | 列表数据源：各渠道的策略与今日状态（含 `known`：该群是否已有对话），加载状态（加载中 / 已加载 / 失败）；每次读取编号，只有不早于屏幕上那次结果的读取结果才能改变屏幕，慢的旧回答既不会把后来已不在的渠道带回来，也不会盖掉后来成功的列表；失败时保留屏幕上的列表；`refresh` 供写入之后读回，`retry` 供失败提示重试 |
| `useKnownChannelGroups.ts` | 新增表单的候选群聊数据源：每次打开表单时查询（对话会在页面开着时出现），只有最新那次回答落地，等回答期间屏幕上已有的候选保留；查询失败时候选区不显示而不弹提示（键仍可手输）；`load` 永不抛出 |
| `useChannelAudit.ts` | 审计状态：同一时刻只展开一个渠道；展开另一个渠道或收起当前渠道会作废在途的请求，已不展开的渠道的迟到回答不会落到现在展开的渠道上；加载失败显示「无法加载」而不是「暂无数据」，再次展开即重试；占比条按审计窗口合计取份额，与渠道今天的花费无关；窗口天数 `AUDIT_DAYS` 导出，展开按钮的文案用同一个数 |
| `ChannelBudgetCard.tsx` | 单个渠道的卡片：今日花费与上限、用量条、上限输入框与启用开关、删除按钮（名称含渠道名，卡片多张时可区分）、可展开的发送者审计（展开按钮带 `aria-expanded`，文案写出天数）；`known` 为 false 时用中性文字说明该群还没有对话记录；标题（标签，没有标签时是渠道键）与审计里的发送者 ID 都不截断：未命名的渠道只靠键区分、发送者只靠 ID 区分，所以放不下时先让花费与删除按钮（审计行里是消息数、占比条与花费）另起一行，标识自己仍比卡片宽才在标识内断行（按卡片自身的宽度换行，不看视口断点）；自己数着本渠道在途的保存（上限与开关可以同时在存），删除按钮恰好在其中一次未落定时不可用，与别的渠道无关；区间外的上限在这里弹出说明、不发出；删除只发起请求，确认由面板负责 |
| `ChannelBudgetAddForm.tsx` | 新增渠道表单（`<form>`，保存按钮是唯一的提交按钮，任一输入框里按 Enter 等同点保存，取消是 `type=button`）：候选群聊、渠道键、可选标签（保存时去掉首尾空白）与每日上限；上限以文本持有、保存时才解析，所以可以清空后重新键入，渠道键或上限为空时保存按钮不可用（Enter 同样不发），区间外的上限弹出说明、不发出、表单保持原样（表单关掉浏览器自带的区间校验，否则说明会被浏览器的提示抢先）；表单自己跟踪自己的请求，与渠道卡片的保存互不影响；取消或请求失败时保留已键入的内容，成功添加后回到默认上限（2），并在列表读回之后收起 |
| `ChannelGroupPicker.tsx` | 候选群聊选择器：每个候选是以渠道键为文字的胶囊按钮（`type=button`，在表单内；`aria-pressed` 标出与键输入框相等的那个；键比选择区宽时在按钮内断行、不截断，两个群不会看起来一样），点选把键填进输入框；没有可说的（回答之前、查询失败）时不渲染，回答为空时说明暂无可选群聊；不显示群名 |
| `ChannelLimitInput.tsx` | 渠道每日上限的行内输入框（失焦保存，Enter 等同离开输入框、走同一条失焦路径，Esc 丢掉键入的文字且不保存；除了还没被失焦处理过的键入文字，框显示当前生效的上限，所以保存被拒、清空或键入的数等于生效上限时，框在那次失焦处理完后回到生效值，被拒的数不会留在框里、也不会在下一次失焦时再发出去；草稿等保存结束才清掉，且只清掉这次失焦处理的那段文字，保存进行中又键入的文字是下一次编辑，留在框里并在下一次失焦时发出；保存成功后新策略读回之前框里仍是键入的数；接受区间内任意金额（`step="any"`），无障碍名称由调用方传入） |
| `channelLimit.ts` | 每日上限的区间（0.01 至 10000 美元，两端都可存，与服务端对已存策略和新建请求体的约束一致）与区间判断；NaN（清空的框）不在任何区间内 |
| `__tests__/channelBudgetTestKit.ts` | 面板测试的共享素材：两个渠道键、状态（可指定 `known`）/ 策略 / 审计条目的构造、带取值的翻译替身（模块级单一引用，`verify:stable-mocks` 要求）、展开按钮文案 `AUDIT_TOGGLE` 与垃圾桶按钮名称 `trashName`、`nextTick` |
| `__tests__/ChannelBudgetSection.test.tsx` | 面板单测：展开审计后各发送者的占比条取自窗口合计，渠道今天花费为 0、小于或大于窗口合计时都一样；窗口花费为 0 时条为空；上限的保存还在进行时点开关，两次保存各自只带自己的字段（先 `{ daily_limit_usd }`、再 `{ enabled }`）；新增渠道走整条创建、不走更新；上限框：保存被拒后回到生效上限且再次进出不重发，清空后失焦不发请求并回到生效上限，键入的数等于生效上限时不发请求，保存成功后新策略读回之前框里仍是键入的数，保存进行中又键入的文字（保存成功或被拒两种结局）留在框里且下一次失焦发出；新增渠道的上限框：清空后可重新键入、小数可从头键入、框为空时保存按钮不可用、成功添加后回到默认上限；创建被拒时表单保持打开并保留已键入的渠道键、标签与上限，创建成功时表单在列表读回之后才收起；两个上限框都有名称且接受区间内任意金额 |
| `__tests__/ChannelBudgetSection.guards.test.tsx` | 面板拒绝发出什么：区间外的上限（0、0.001、10000.5、-5）不发请求、弹出带区间的说明、框回到生效上限，区间两端（0.01、10000）照常发出；新增渠道的上限在区间外（0、10001）不创建、表单保持已键入的内容；删除走真实确认对话框：点垃圾桶（按钮按渠道命名）只询问（写出渠道名）不发请求，取消不发请求且渠道保留，确认后删除该渠道并显示读回的列表，删除被拒时对话框关闭且渠道保留 |
