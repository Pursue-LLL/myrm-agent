# src-tauri 模块架构

[INPUT]
- `sidecar/build.py` 产物（POS: Python Backend 二进制）
- `myrm-agent-frontend` standalone 资源（POS: WebView Release 资源）

[OUTPUT]
- Tauri 桌面二进制构建配置
- IPC 命令注册清单、权限清单、Runtime Rust 源码根

[POS]
Tauri 工程根目录。负责构建清单、权限与命令注册元数据、以及 `src/` Rust 运行时代码装配入口。

## 架构概述

`src-tauri/` 不是业务实现叶子层，而是桌面构建与运行时配置枢纽：Cargo/tauri 配置、权限声明、命令注册清单和 Rust 源码根协同组成可发布桌面壳。

父模块：[../_ARCH.md](../_ARCH.md)

## 文件清单

| 文件 | 地位 | 职责 | I/O/P |
|------|------|------|-------|
| `Cargo.toml` | 核心 | Rust crate 依赖与构建配置 | — |
| `build.rs` | 核心 | 构建期命令注册与权限对齐校验入口 | ✅ |
| `tauri.conf.json` | 核心 | Tauri 窗口、资源、bundle 与 updater 配置；`plugins` 段只能出现已注册插件认得的键（插件配置多为 `deny_unknown_fields`，错键即启动 panic，由 `app::chain` 的进程内启动测试把关），其中 `plugins.shell.open` 是 `shell:allow-open` 唯一的链接白名单 | ✅ |
| `command_registry_macro.in` | 核心 | 命令名/处理器单一注册源（`build.rs` / `app/mod.rs` / `ipc_security/capability.rs` 共用） | ✅ |
| `src/` | 核心 | Rust 运行时代码根 | [src/_ARCH.md](src/_ARCH.md) |
| `permissions/` | 核心 | Tauri command ACL（含 autogenerated） | — |
| `capabilities/` | 核心 | 静态能力清单：仅 `curtain.json`（帷幕窗口页，自定义协议来源属 Local，只放行 `curtain_report_physical_input`）。产品页（`main` / `session-*` / `pet-surface`）的授权不在此处：它依赖运行期端口，由 `src/ipc_security/capability.rs` 在启动期注册 | — |
| `frontend-shell/` | 核心 | Release 模式 WebView 占位页 | [frontend-shell/_ARCH.md](frontend-shell/_ARCH.md) |
| `icons/` | 资源 | 打包图标资产 | — |
| `entitlements.plist` | 核心 | macOS Hardened Runtime 权限声明 | ✅ |
| `Info.plist` | 核心 | macOS 应用基础元信息 | — |
| `binaries/` | 产物 | sidecar 二进制输出目录（构建期使用） | — |
| `gen/` | 产物 | Tauri 生成 schema 目录（本地生成） | — |

## 约束

- `src-tauri/binaries/`、`src-tauri/gen/`、`src-tauri/target/` 均属于构建产物域，不承载业务源码。
- 命令注册必须只改 `command_registry_macro.in`，禁止在 `build.rs` / `app/mod.rs` / `ipc_security/capability.rs` 重复维护命令列表。
- 产品页的 ACL 授权只有一个来源（`ipc_security/capability.rs`：发送方闸门 × 命令注册表推导，加最小权限的插件/核心表）。不要再新增静态 `capabilities/*.json` 去授权产品窗口——release 下产品页是 `http://127.0.0.1:<port>`，被 Tauri 判为 Remote，静态文件写不出运行期端口，只在 dev 的 Local 来源下看似可用。
