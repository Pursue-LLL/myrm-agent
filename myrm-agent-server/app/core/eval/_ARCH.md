# app/core/eval 模块架构


---

## 架构概述

`eval` 模块是 Myrm Agent Server 提供的 Agent 评估与回归测试的核心业务引擎。它作为 `myrm_agent_harness/eval` 框架层的具体实现，负责桥接框架的 `AgentExecutor` 协议和 Server 的 `AgentFactory` 业务逻辑。

## 核心设计原则

1. **单机沙箱策略**：评估用例和报告均持久化在用户专属的本地 `.myrm/` 目录下，不依赖外部数据库。
2. **异步非阻塞**：评估套件的执行可能非常耗时，因此采用异步后台任务（BackgroundTasks）运行，通过内存状态字典（`_eval_state`）提供实时的进度查询。
3. **引擎解耦**：本模块不关心具体的断言逻辑（由 Harness 层负责），只负责提供执行环境和生命周期管理。

## 文件清单

| 文件 | 职责 |
|------|------|
| `adaptive.py` | 并发让出基础设施：`mark_chat_activity`（前台 ChatService 心跳）+ `AdaptiveEvalManager`（评测后台任务检测到前台活动时智能让出算力）。被单评测、Matrix、Memory A/B 三个编排共同复用。 |
| `datasets.py` | 数据集文件层：`.myrm/eval_datasets/` 下 JSONL 数据集发现（`get_dataset_path`/`get_all_datasets`）与读写（`get_eval_cases`/`save_eval_cases`），含 legacy `eval_cases.jsonl` 迁移。 |
| `reports.py` | 单评测报告文件层：`.myrm/eval_reports/` 下 `latest.jsonl` 摘要与历史报告读取（`get_latest_report_summary`/`get_all_report_summaries`）。 |
| `executor.py` | 实现了 `LocalEvalExecutor`，适配 Harness 的 `AgentExecutor` 协议。始终以 `unattended_mode=True` 运行（跳过 ask_question_tool 工具注册 + 注入无人值守系统提示词），防止自动化评测被 HITL 交互阻塞。支持接收 `profile_id` 动态覆盖 Agent 属性（含 `ResolvedAgentProfile` 的 builtin tools、`auto_restore_domains`、`memory_decay_profile`）；profile resolve 后（`benchmark_mode` 清空前）经 **`profile_output_suffixes`** 注入 personality + `response_locale_policy` 至 `user_instructions` 尾；并解析 profile/eval/chat 绑定的 Shared Context 注入记忆运行时（支持 **`resolve_shared_contexts` 开关**：分层能力消融评测显式传 `False` 隔离用户真实共享上下文，避免把「共享记忆」混入「记忆能力」的测量，交互式矩阵评测保持默认开启以镜像真实会话）。支持 `benchmark_mode` 基准模式：清空 system prompt、禁用扩展工具/技能/MCP/子 Agent/共享记忆/Web 搜索，关闭 replan，确保公平基准对比；**`benchmark_tools` 白名单**（由基准注册表声明，如 BrowseComp 的 `("web_search",)`）在 CORE file/shell 基线之上按需注入，修复了「基准模式一刀切禁用全部工具导致 Web 类基准不可跑」的工具面缺陷；**`max_tool_calls`/`max_iterations` 双上限透传**（基准 spec 声明时注入 `engine_params.max_tool_calls` 与 `agent_max_iterations`，未声明则沿用引擎默认，测量衰减防护）；**`blocked_hostnames`/`blocked_terms` 去污染 blocklist 透传**（经 `GeneralAgentParams` → 工具装配注入 web_fetch/web_search 工具，仅 benchmark_mode 生效，正常产品工具不受影响）。支持 **`skill_ids_override`**：None 保持 profile 声明技能、[] 完全禁用、列表固定技能集合——profile resolve 后应用，作为分层评测技能消融的最终开关。捕获 Agent stream 事件：TOKEN_USAGE 填充 `AgentResponse.token_usage`；**`tasks_steps` 采集工具调用明细**（tool_name + step_key + detail + 错误摘要）填充 `tool_call_details`，**`engine_limit_reached` 记录 `limit_reached`**（如 `max_tool_calls`/`max_replan_attempts`）、**`iteration_limit_reached` 映射为 `max_iterations`**（LangGraph 递归预算耗尽由独立事件发出，不映射则迭代截断用例静默丢失截断标记），**`error_category`（规范枚举 `ToolErrorCategory.BENCHMARK_BLOCKED`）累加 `blocked_count`**（去污染守卫拦截计数），完整披露评测轨迹供报告审计。包含评测工作空间的物理防污染隔离，为每个并发执行的用例动态分配沙箱内的专属独立路径 (`.myrm/eval_workspaces/`) 彻底杜绝测试资源文件竞态冲突。支持 `workspace_seed_map`：外部数据集（如 WorkBuddy Bench）预置的只读任务工作区会在用例执行前拷贝进会话隔离目录。**workspace 生命周期清理**：`create_session`/`execute` 将物理会话目录登记进 `_created_workspaces`，编排 finally 统一调用 `cleanup()`（`asyncio.to_thread` + `shutil.rmtree(ignore_errors=True)` 幂等删除）并在 `_ARCH` 声明模块级 `cleanup_orphan_eval_workspaces()` 供 server 启动时清扫历史孤儿目录，保证 eval 运行「用后即焚」不遗留磁盘垃圾（与 hermes-agent `evals/readtool` 的 `tempfile.mkdtemp + finally rmtree` 竞品实践对齐）。 |
| `matrix.py` | Matrix 评测：`run_matrix_eval_background` 跨配置矩阵评测——同一数据集在多个 AgentProfile 上顺序执行，输出 stable/regression 分类报告；配套 `get_matrix_eval_status`/`abort_matrix_eval`/`get_latest_matrix_report` 与 **报告历史读取**（`get_matrix_report_history`/`get_matrix_report`：按时间戳读取 `.myrm/matrix_reports/matrix_report_{ts}.json`，history 返回轻量摘要列表（timestamp/dataset/profile/eval_type/模型/stable_rate/limit/aborted）供前端历史表展示，支撑 HLR 持续度量闭环），报告存 `.myrm/matrix_reports/`。报告含 **`judge_model` 披露**（经 `model_config._resolve_judge_config` 解析用户 model_cfg 注入 `MatrixRunner` 保证多 profile 同一判分模型，与 memory_ab/layered 口径一致，换主模型后分数漂移可追溯）与 **per-profile `agent_model` 披露**（每个 profile 声明模型独立解析），并带 **`aborted` 标记**（用户中途 abort 后部分结果不会被误读为完整运行）。矩阵评测无下载阶段，启动即置 `stage: "evaluating"`，收尾 finally 统一清理 `stage`/`download_progress`（防止 layered 下载阶段残留污染后续矩阵展示）。矩阵各 profile 的会话 workspace 在 finally 统一 `LocalEvalExecutor.cleanup()` 用后即焚；每个 executor 的 cleanup 独立 try/except 防护，单个 profile 清理失败不阻断其余 profile。作为分层评测门面，re-export `layered.py` 的 `LayerSpec`/`DEFAULT_LAYER_SPECS`/`layer_specs_to_meta`/`run_layer_eval_background`；进度状态与 runner 绑定均经 `_state.py` 模块属性读写（跨模块 abort 依赖）。 |
| `_state.py` | 共享评测状态：`matrix_state`（统一进度字典，含 `stage`/`download_progress` 进度键，评测启动与收尾统一初始化/清理）、`active_matrix_runner`（当前编排中的 runner 绑定，跨模块必须经模块属性读写）与 `DEFAULT_MATRIX_REPORTS_DIR`（报告目录）。Matrix 与分层两套编排复用同一状态机与报告目录，本模块是避免 matrix/layered 循环依赖的唯一协调点。 |
| `layered.py` | **分层（配置增量）评测**：`LayerSpec` 描述单层开关组合（`benchmark_mode`/`skills_enabled`/`memory_enabled`）并以 `fingerprint()`（sha256 摘要，12 位）锁定组合；`DEFAULT_LAYER_SPECS` 定义 bare→core→skills→memory 四层递增链路——bare 为 benchmark_mode 公平剥离基线，core 为完整 agent 配置（规则/replan/MCP 等 harness 基础能力，技能与记忆关闭），skills/memory 逐层叠加，相邻层差即被启用能力的增量；报告含 `harness_version`（跨版本可比，测量衰减防护）与 `eval_type: "layered"`（与 matrix 报告区分）；`layer_specs_to_meta` 生成报告 `layers` 元数据；`run_layer_eval_background`/`_run_layer_eval` 复用 `MatrixRunner` 逐层执行（每层一个 `LocalEvalExecutor`：bare 走 benchmark_mode，core 清空技能，skills 开启 profile 技能，memory 额外开记忆并隔离记忆目录；**所有层 `resolve_shared_contexts=False`** 隔离用户真实共享上下文，保证「记忆层增益」只反映记忆机制本身），报告写入 `matrix_reports/` 并含 `layers` 元数据与 `agent_model`/`judge_model` 披露、**per-layer `memory_tool_calls`**（区分「记忆未帮助」与「记忆从未被使用」，与 memory_ab 口径一致）、**`max_tool_calls`/`max_iterations` 基准预算披露**（经 `benchmark_run_limits` 读取 spec 声明，报告自述每用例允许的工具调用/迭代上限，测量衰减防护）、**`decontam_active` 披露**（经 `benchmark_decontam` 解析 HF blocklist 是否生效）与 **`aborted` 标记**（中途 abort 的部分结果不误读为完整运行）；进度经 `_state.py` 共享状态透出，**下载阶段用 `stage: "downloading"` + `download_progress` 上报真实字节进度**，评测阶段切回 `stage: "evaluating"` + 用例进度，与矩阵复用同一状态机。 |
| `memory_ab.py` | **Memory A/B 评测**：`run_memory_ab_background` 复用 `MatrixRunner` 在**任意外部基准**（`benchmark_id`，含 WBBench 子集与 BrowseComp 等注册基准）上并行对比 `enable_memory=True/False` 两种 agent 配置，配合 `LocalEvalExecutor` 的 `memory_base_path` 隔离参数与 `create_memory_manager` 的 `base_path` 注入，将对照组记忆写入会话级临时目录 `.myrm/eval_memory_ab/` 并在结束 `evict_cached_memory_manager` 清理（含释放 harness 嵌入式 Qdrant 单例缓存）后删除，杜绝污染用户真实记忆；双臂 executor 的会话 workspace 在 finally 一并 `LocalEvalExecutor.cleanup()` 用后即焚；报告在 per-profile summary 中追加 `memory_tool_calls`（统计每臂真实调用 `memory_*` 工具的次数，用于区分「记忆未帮助」与「记忆从未被使用」，规避测量衰减）；双臂统一注入基准声明的 `benchmark_tools` 白名单（如 BrowseComp 的 `web_search`）与 **`benchmark_run_limits`/`benchmark_decontam` 解析的预算（`max_tool_calls`/`max_iterations`）与 HF blocklist**（web-research 基准去污染，报告披露 `max_tool_calls`/`max_iterations`/`decontam_active`，与普通 benchmark 单跑/分层评测同口径）；接受 `limit` 透传给 `build_benchmark_cases` 做抽样（报告 `limit` 仅在实际抽样时记录，全量跑为 null）；**模型披露**：报告写入被评测 agent 模型 `agent_model`（经 `model_config._resolve_agent_model_label` 解析，profile 声明优先、兜底 model_cfg，与 benchmark manifest 口径一致）与判分模型 `judge_model`（LLM judge 基准经 `model_config._resolve_judge_config` 解析用户 model_cfg 注入 `MatrixRunner` 保证双 arm 同一判分模型，native 基准为 `none`），换主模型后两次分数漂移可追溯，报告另含 **`harness_version` 披露**（跨框架升级分数可比，与 matrix/layered 口径一致），并带 **`aborted` 标记**（用户中途 abort 后部分结果不会被误读为完整运行，与 matrix/layered 口径一致）；WBBench（native/composite 确定性判分）跳过 judge 解析避免无谓配置加载。配套 `get_memory_ab_status`/`abort_memory_ab`/`get_latest_memory_ab_report` 支持进度查询、熔断与报告读取，`get_memory_ab_report_history`/`get_memory_ab_report` 支持按时间戳倒序列出历史报告摘要（摘要含 `limit` 抽样披露与 `agent_model`/`judge_model` 双模型披露）并回看指定报告（报告存 `.myrm/memory_ab_reports/`，损坏文件跳过并告警）。 |
| `service.py` | 单评测编排服务：`run_eval_suite_background`/`run_eval_suite` 异步调度器（支持 `external_cases` 跳过 JSONL 加载、`workspace_seed_map` 透传做工作区预置、`benchmark_mode`、**`benchmark_tools` 白名单透传**、**`max_tool_calls`/`max_iterations` 预算与 `blocked_hostnames`/`blocked_terms` HF blocklist 透传至 executor 并写入 manifest**）、`run_benchmark_background`/`run_benchmark_download_background` 泛化基准编排（WBBench 子集 + 注册第三方基准统一流程，复用同一 SSE 状态机，`stage`/`stage_subset_id`/`download_progress` 分阶段实时展示进度，`abort_eval` 在下载阶段经 `abort_requested` 联动下载流 `should_abort` 实现可取消下载；`run_benchmark_background` 接受 `limit` 抽样数，经 `build_benchmark_cases` 以固定 seed 从全量用例中抽取子集，控制成本与时长；`sample_size` 仅当 `build_benchmark_cases` 返回 `sampled=True` 时写入 manifest，全量跑不标 sampled；**运行前解析 `benchmark_run_limits`/`benchmark_decontam`，将 spec 声明预算与 HF blocklist 注入普通单跑路径**——BrowseComp 单跑即受 `max_tool_calls=100`/`max_iterations=150` 约束并屏蔽 HF 访问，与分层/记忆 A/B 同口径）、`run_wb_bench_background`/`run_wb_bench_download_background` 作为 legacy 兼容入口委托到泛化流程；模型解析由 `model_config.py`、manifest 构建由 `manifest.py` 分别提供；summary 透出 `avg_pass_rate`（EvalResult 聚合的每轮 test pass rate 均值，供前端赛道卡片区分展示）与 `decontam_active`（HF 去污染是否生效，与分层/A-B 报告同口径）。 |
| `manifest.py` | 评测环境快照构建：`_build_eval_manifest` 捕获 profile 模型（provider/id 拆分）、引擎参数（`thinking_effort`/`max_tokens`）、tool policy、提示词指纹（sha256）、任务集哈希（文件内容或外部用例 pickle，序列化异常时降级为 `external-{dataset_id}` 稳定标记）并记录 `judge_model`（LLM 判分基准所用模型，供前端报告展示）、`limit`（抽样披露，仅实际抽样时非空）与 `max_tool_calls`/`max_iterations`（基准声明预算披露，测量衰减防护）；模型未声明时经 `model_config._resolve_agent_model_label` 兜底解析，保证与 Memory A/B 报告披露口径一致。 |
| `model_config.py` | 模型配置统一解析：`_resolve_agent_model_label`（profile 声明模型优先、兜底用户 `model_cfg`，不可解析时为 `unknown`）被 manifest 与 memory_ab 报告共同消费，保证两处披露口径一致；`_resolve_judge_config` 从用户 `load_user_configs` 的 `model_cfg` 解析出 `JudgeConfig`（model/api_key/api_base），注入 `EvalRunner`/`MatrixRunner`，使 LLM-as-a-Judge 复用用户自配的判分模型与凭据（替代框架默认的 `gpt-4o-mini` env 兜底），未配置模型时返回 `(None, "none")` 供 router 前置检查与 native 基准跳过。 |
| `benchmarks.py` | **外部基准统一目录门面**（业务层）：合并 WBBench 专属适配器（`wb-bench-` 前缀）与框架注册表注册的第三方基准（如 BrowseComp、Operational Assurance Suite）为单一 catalog，供前端与 eval 服务消费。`list_benchmark_sources` 返回带本地状态与 `benchmark_id`/`provider`/`supports_memory_ab` 的完整卡片数据；`ensure_benchmark_source`/`build_benchmark_cases` 按 `benchmark_id` 分发到对应适配器（下载 / 构建可运行用例 + 工作区种子映射）；**`limit` 抽样**：`build_benchmark_cases` 接受 `limit`，在 `limit>0` 且小于全量时以固定 seed 42 随机抽样（`random.Random(42).sample`）保证可复现，同步裁剪 `workspace_seed_map`（按被抽样 case 的 message 匹配），实现小样本快速验证；返回 `(cases, seed_map, sampled)` 三元组，`sampled` 仅在真实抽样时置 True（limit 达到/超过全量视为全量跑），供 service/memory_ab 统一披露；`benchmark_required_tools` 解析基准声明的 `required_tools` 白名单供 `benchmark_mode` 注入；`benchmark_needs_judge` 判定基准是否由 LLM judge 判分（WBBench 为 task-native 否，注册基准看 spec.scoring），供 router preflight 与 memory_ab 共用；**`benchmark_run_limits` 读取 spec 声明的 `max_tool_calls`/`max_iterations` 预算**（WBBench 未声明返回 `(None, None)` 沿用引擎默认）；**`benchmark_decontam` 解析 HF 污染 blocklist**（web-research 基准——声明 `web_search`/`web_fetch` 工具——返回 `HUGGINGFACE_DOMAINS`/`HUGGINGFACE_QUERY_MARKERS` 守卫，无 web 工具基准返回空，供 layered 注入执行器）。 |
| `operational_assurance/` | **运行保障审计套件（Operational Assurance Suite）**：覆盖 6 大企业级故障场景（权限拒绝、工具超时、发布/会话恢复、沙箱枯竭、Skill 冲突、证据过期）的确定性评测用例与沙箱预置种子。`adapter.py` 发布 `BenchmarkSpec(id="operational-assurance")` 注册到 Harness 注册表；`fixtures.py` 提供纯净无漂移的 multi-turn 测试用例构造与 seed 工作区。 |
| `browse_comp.py` | **BrowseComp 适配器**（OpenAI 网页研究基准）：从官方加密 CSV（`openaipublic.blob.core.windows.net`）下载（SHA256 校验 + 指数退避重试 + 可取消下载），按官方 canary XOR 方案解密 `problem`/`answer` 列，构建 `MultiTurnEvalCase`；判分采用 harness `SemanticAssertion` LLM-as-a-Judge（judge prompt 复刻官方 BrowseComp 评分规则，含括号组互换/矛盾/遗漏判定）；声明 `required_tools=("web_search",)` + `supports_memory_ab=True` + **`max_tool_calls=100`/`max_iterations=150` 运行预算** + **`judge_prompt=BROWSECOMP_JUDGE_PROMPT` 随 spec 发布**，模块导入时经 `register_benchmark` 注册进框架基准注册表。 |
| `skill_ab.py` | **Skill A/B 评测**：`run_skill_ab_background` 基于三臂对照体系（No-Skill / Baseline / Candidate）使用 `MatrixRunner` 针对技能演进进行隔离跑分与 Delta 综合裁决，报告持久化在 `.myrm/skill_ab_reports/`。 |

## 依赖关系

- **内部依赖**：
  - `myrm_agent_harness.eval`：提供核心的评估引擎、断言协议（`SemanticAssertion` 等）、报告器，以及基准注册表（`register_benchmark`/`list_benchmarks`/`get_benchmark`）。
  - `app.ai_agents.agents.AgentFactory`：用于实例化真实的业务 Agent。
  - `app.core.sandbox.local_executor.LocalExecutor`：提供沙箱环境的命令执行和文件读写能力。
  - `app.services.memory.shared_context`：提供评测运行时 Shared Context 绑定解析。
- **被依赖**：
  - `app.api.eval.router`：API 层调用本模块的服务（单评测 + WBBench）。
  - `app.api.eval.benchmarks_router`：外部基准统一 HTTP 层（`/eval/benchmarks` + legacy `/eval/wb-bench`），调用 `app.core.eval.benchmarks` 与 `app.core.eval.service`。
  - `app.api.eval.matrix_router` / `app.api.eval.memory_ab_router`：分别调用 `app.core.eval.matrix` / `app.core.eval.memory_ab`；matrix_router 经 matrix 门面调用 `layered.run_layer_eval_background` 提供 `/matrix/layers-run` 分层评测入口。
