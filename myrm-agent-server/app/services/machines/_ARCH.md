# services/machines 模块架构

## 架构概述

进程内的机群注册表与接管会话状态。`MachineService` 是单例：启动时放入两台示例节点（指标是固定数值，没有采集器）；`generate_registration_token` 按平台生成一条带新令牌的接入命令，服务端既不保存也不校验这枚令牌；`initiate_takeover` / `release_takeover` 只在内存里切换节点状态与接管会话（Agent ⇄ Human）。本包不连接真实机器，也不传输屏幕画面。

## 文件清单

| 文件 | 地位 | 职责 | I/O/P |
|------|------|------|-------|
| `machine_types.py` | 核心 | 平台与状态枚举、指标快照、机器节点、接入命令与接管会话 Pydantic 契约 | ✅ |
| `machine_service.py` | 核心 | 单例服务：示例节点注册表、接入命令生成与接管状态切换 | ✅ |
| `__init__.py` | 门面 | 导出公共类型与单例服务 | ✅ |

## 约束

- **进程内状态**：注册表与接管会话只存在于当前进程，重启后回到两台示例节点。
- **接管是状态位**：接管只切换节点状态与会话状态；屏幕流与输入透传不在本包内。
