# cron 模块架构

Cron 业务服务层。提供定时任务创建前的手动成功验证门禁、投递目的地的健康度判断与先验执行统计服务。

---

## 架构职责

- `prerequisite_service.py`: 统计指纹工作流在历史 Chat 与 Kanban 中的手动执行成功次数，提供先验验证门禁。
- `delivery_health_service.py`: 判断一个投递目的地（渠道 + 地址）最近的投递是否健康。哪些任务投递到同一目的地，由任务保存的投递配置认定；一次运行只算进它实际投递到的目的地，由运行记录里的 `delivery_key`（执行器写下的目标指纹，来自 harness 的 `delivery_target_key`，渠道与地址都相同才是同一个）认定，没有该字段的运行不计入；指纹取自未脱敏的地址，所以只差一个密钥的两个机器人不会并成一个。只看发生过投递尝试（delivered 或 failed）的运行，按结束时刻取最近 24 小时内的最近 50 次，跳过投递的运行不计入；连续失败数与最近一次失败的类别、时间都只来自投递记录，任务自身的失败不算投递故障。三态判定归应用层：连续失败 3 次，或最近一次失败是认证失败、地址被拒（重试修不好）为 DOWN，仍有失败为 DEGRADED，否则 HEALTHY；无需外发的渠道（`NON_OUTBOUND_CHANNELS`）和窗口内没有投递记录的目的地没有结论。最近一次失败的时间是该运行的结束时刻（取于投递之前），以 UTC 给出（SQLite 读回的是不带时区的时间，经 `as_utc` 补上）。

## 文件清单

| 路径 | 地位 | 职责 |
|------|------|------|
| `__init__.py` | 模块入口 | 暴露 Cron 业务服务公共符号 |
| `delivery_health_service.py` | 核心服务 | 判断投递目的地（渠道 + 地址）健康度的服务；三态枚举与判定阈值在这里 |
| `prerequisite_service.py` | 核心服务 | Cron 任务前置验证门禁服务与统计聚合 |
