# streaming_support 模块架构

Agent 流式传输辅助工具层，供 orchestrator、reconnect 与 API 流式路由复用。

## 文件清单

| 文件 | 地位 | 职责 | I/O/P |
|------|------|------|-------|
| `sse_helpers.py` | 核心 | SSE 格式化与解析：错误 chunk 生成、压缩耗尽检测、审批超时 / 澄清中断帧识别（纯解析，无调度副作用） | ✅ |
| `hitl_timeout.py` | 核心 | HITL 中断超时的武装与恢复 SSOT：`arm_interrupt_timeout`（审批 300s / 澄清 900s，优先级 clarify > approval；已停在中断但未武装的流（如计划确认、浏览器接管）立即 `reopen` 调度键，使其后的 resume 不被误判为已被超时处理）；两类超时回调共用 `_resume_after_timeout`：在 `server_turn_lease` 下运行（先抢占会话并注册取消令牌，用户同时新开回合时放弃本次恢复并 `reopen`；聊天「停止」与 E-Stop 能到达该回合，被取消时结束它启动的后台任务，回合结束归还）→ 以 `Command(resume=…)` 经 gateway 运行续写 → 澄清把已落库的卡片标记已答复并写入 `answerRecord`（`HitlAnswerRecord`：`by: user|timeout` + 续写值；先于持久化续写，续写里的新卡片保持未答复；标记落库失败只记警告，不丢续写）→ 持久化续写（与请求回合共用公开的 `assistant_turn_payload` 构造存库形态：citation 标签抽成 `citations`、memory 元数据、用户时区；回合有可存内容就存，含只带澄清卡、没有正文的回合）→ 武装下一个中断；拿到会话后续写的 collector 用 `take_over_chat` 顶替该 chat 的登记（与页面发起的 resume 一致）：期间重载的页面接上的是这一轮的快照与实时事件，续写停在新卡片上时这张卡由这一轮的 collector 握着（`turn-state` 的 `awaitingApproval` 为真、重载能取回；原先没有 collector 握着它，页面当作空闲直到下一个计时器到点），被答复的卡片随停着的那一轮一起退出登记，不再需要摘卡；续写结束后 `_end_turn` 与请求回合的 finalize 对齐：`schedule_compaction_drain`、压缩遥测与任务指标释放（停在新卡片时同样释放）；没有新中断时再 `commit_run_history_sync` 记录线程与存储对话一致（让下一轮沿用线程而不是重建）、`close_run_digest` 收尾 run digest 并发布 `session_completed` / `session_failed`（出站 Webhook 与推送通知的来源）、`cleanup` 自己的登记（期间用户新开的回合已顶替它则不动；回合被取消时同样结束）；运行抛错时重开调度键并 `hand_chat_back` 把登记还给停着的那一轮（它的卡片原样还在：答案没有被消费，人工回答要有卡片可点） | ✅ |
| `sse_failover_emitter.py` | 核心 | harness `FailoverEmitter` 协议的 SSE 适配器：把模型故障转移/恢复事件桥接成 `model_failover` / `model_recovery` SSE chunk，并通过 race-style merge 与主 chunk 流交错输出；主流每一步共用同一个 `contextvars.Context`，运行在某一步设下的 ContextVar（工作区信任、执行器）后续步骤仍可见 | ✅ |
| `stream_collector.py` | 核心 | 流内容收集器（每种事件类型由一个 `_on_<事件类型>` 方法处理，`_EVENT_HANDLERS` 表按事件类型分发；回复文本经 harness `AnswerDraft`：模型切换等恢复重放只丢最近一次工具步骤之后的在途段落，之前已落定的文字保留）；`tool_result_details` 捕获并落库入 `extra_data.tool_result_details` 供会话树分支状态折叠；memory citation 持久化；`tasks_steps` 按 `tool_call_id` merge；成功 `skill_manage_tool` step 注入 `skill_mutation_batch_id`（SSE+落库）；`tool_evicted_ref` 绑定 progressStep（tool_call_id 优先）并持久化 `evicted_stored_chars/evicted_total_lines/evicted_storage_truncated`，支持分 stream（`stdout`→`evicted_file_ref` 系、`stderr`→`evicted_stderr_file_ref` 系，stderr 认领不受 stdout 已认领影响）；先于 step 到达的 evicted 引用进入 pending 队列，`tasks_steps`/`message_end` 阶段按 step 认领且 stdout+stderr 不互相覆盖；`message_end` 指标归档（usage/cost/tokenEconomics/`stream_ttft_ms`→`streamTtftMs`，以及 harness 披露载荷 `deliverable_tier`→`deliverableTier`、`staged_artifacts`→`stagedArtifacts`，供回答证据档徽章与暂存草案横幅渲染）；`kanban_add_task`/`cron_manage` 成功结果写入 extra_data；`clarification_required`→`extra_data.clarification`；`status.phase=plan_confirm|clarify`→`planConfirmation`/`clarification.answered`（`clarify` / `resolved` 同时保留事件携带的 `answerRecord`）；reasoning 落库前执行 sanitize+scrub，且采用字符预算上限并在截断时写入 `reasoningTruncated/reasoningCharLimit` 元数据；**restart 协议**：凡会使 LLM 从头重跑本轮的恢复（failover STATUS `model_failover`/`safety_fallback_active`、`transient_retry`、`empty_response_recovery`、`tool_call_retry`、`vision_fallback_recovery`、`media_rejected_recovery`、`context_compaction` 等 `restart:true` STATUS、`model_escalated` 事件）均通过 `_discard_draft` 幂等清空已收集的 content/reasoning 废稿（主模型失败前流出的部分内容会被 fallback 从头重跑覆盖，持久化不能拼接废稿+完整回答）；failover STATUS 与 `model_failover` SSE 双通道合并为单条 progress step（`_append_failover_step` 按 `model_failover*` 前缀或 `safety_fallback_active` 去重并取更完整的 from→to 标签）；`model_escalated` 事件同样持久化 `model_escalated` progress step（from→to 标签），与实时展示一致；`_sync_run_digest` 推送 RunDigest 至 `RunDigestStore`；`tool_end` 携带 `skill_mutation_batch_id`（`ServerSkillManageBatchHook` 提交后经工具进度通道广播）时由 `mutation_batch_stream.link_batch_to_step` 关联到最新未关联批次的 skill_manage 步骤，随 `progressSteps` 落库；loop guard 的 `tool_stuck` 暂停（`approval_required`，经 `collect_tool_stuck_pause` 识别）不进 `_pending_interrupt_events`：没有卡片可答，收集器落一条 `tool_stuck_paused` progress step 并置 `tool_stuck_paused`，本轮按已结束处理（见 `stream_finalize.py`）；实时订阅者仍收到这条事件；`has_pending_tool_approval()` 只看 `tool_approval_request`（澄清卡与 `approval_required` 卡有各自的存储记录），`settle_tool_approvals()` 在审批被答复后把这些卡片从 `_pending_interrupt_events` 摘掉（模块函数 `settle_tool_approvals_of(chat_id)` 取该 chat 当前登记的 collector 并摘卡，页面发起的 resume 经它），停着的 collector 在续跑接手前不会再把已答的卡片重放给新订阅者；超时计时器的续写不摘卡，而是 `take_over_chat(chat_id)` 顶替登记并返回被顶替的那一轮，从这一刻起重载或 attach 的页面拿到续写这一轮（快照、实时事件与它停下的新卡片），被顶替那一轮的卡片原样留在它身上；续写失败时 `hand_chat_back(replaced)` 摘掉自己、把登记还给被顶替的那一轮（期间已有更新的回合接手登记则不动） | ✅ |
| `stream_collector_helpers.py` | 辅助 | `StreamContentCollector` 纯函数：tool 结果解析、HITL clarification/planConfirm 持久化 payload 构建、string-keyed dict 规范化、`collect_tool_stuck_pause`（loop guard 暂停的 progress step）、`merge_tasks_step`（`tasks_steps` 按 `tool_call_id` merge 并注入 `skill_mutation_batch_id`）、迭代上限停止原因的提示文案（`iteration_limit_message`） | ✅ |
| `evicted_output.py` | 辅助 | evicted 工具输出引用的纯函数：载荷规范化（`stdout` / `stderr` 分 stream，预览截断到 8000 字符）、按 `tool_call_id` 优先匹配 progress step（其次同名未认领步骤，最后落到 `bash_code_execute_tool`）、把引用/预览/存储指标写入步骤、判定先于步骤到达的 pending 载荷由哪个步骤认领 | ✅ |
| `citation_persistence.py` | 辅助 | finalize 阶段 citation fallback：当 collector 未写入 `citedMemoryIds` 时，从 harness `MemoryManager.last_cited_memory_ids` 回填 | ✅ |
| `takeover_live_assist.py` | 辅助 | browser takeover 事件的签名 live-assist 链接注入：`inject_takeover_live_assist_url` 给 `browser_takeover_requested` 与 `browser_takeover` 类 `approval_required` 事件写入手机端可打开的 `live_assist_url`（相同请求复用上一条链接，托管浏览器不签发），其余事件原样放行；`TakeoverLiveAssistCache` 由单条流携带 | ✅ |
| `deep_research_stream.py` | 核心 | Deep Research SSE 流 `ai_deep_research_service_stream`：创建 `DeepResearchOrchestrator`，事件经 Gateway 转 SSE；澄清与计划确认两阶段挂在 `PhaseWaiter` 上并以心跳保持连接，流结束或被关闭时清掉两把 waiter 键 | ✅ |
| `multiplexer.py` | 核心 | `WorkspaceMultiplexer` — 全局 SSE 事件总线，单连接把所有会话的状态变化（`session_status`：generating / awaiting_approval / idle）广播给每个标签页，绕过浏览器 6 连接限制；回合正文不经此总线 | ✅ |

## 依赖关系

- `app/schemas/streaming.py` — SSE 信封类型
- `app/core/agent/stop_reason.py` — 停止原因的存储形态与取舍（`stream_collector.py` 用）
- `app/services/agent/params/` — Agent 参数类型
- `myrm_agent_harness.toolkits.llms.fallback` — `FailoverEmitter` Protocol / `with_failover_emitter` 上下文管理器
- `app/services/agent/streaming.py` — `PhaseWaiter`（`deep_research_stream.py` 等它）
- `app/remote_access/pairing*.py` — `takeover_live_assist.py` 签发手机端接管链接
