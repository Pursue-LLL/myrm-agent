# Budget Services Architecture

## 架构概述

服务端预算层：加载并持久化用户预算策略，向 Agent 工厂注入多维预算守卫，按渠道隔离配额，并桥接 harness 的四档渐进花费干预引擎。

## 文件清单

| 文件 | 地位 | 职责 |
| --- | --- | --- |
| `__init__.py` | 入口 | 包标识，不导出符号 |
| `enforcer.py` | 核心 | 预算策略读写、进程级多维预算守卫单例、执行阻断判定与会话预算重置；守卫首次建立时（含保存策略时尚无守卫）按预算日起点（`budget_day.py`）汇总库里的当日花费作为初值 |
| `channel_budget.py` | 核心 | 渠道级日预算策略、守卫注册表与成本记账，避免单个渠道耗尽全局预算；策略的渠道键一律是规范键（库里存的键不论写法，读出时同样规范化；规范键相同的多条策略合并为较严的一条——先取启用的、再取日限额低的——并记一条 WARNING）；重启后每条已存策略都登记进注册表（停用的策略不建守卫、不查成本，仍按停用状态列出），启用策略的当日成本（自预算日起点，见 `budget_day.py`）按渠道键的段边界汇总（`channel_key_extends`），相邻群组不互相计入 |
| `channel_budget_key.py` | 核心 | 渠道预算键的唯一定义：群组的预算键就是它的会话键去掉纪元、话题与智能体后缀（`group_budget_key`，与 `SessionKey.to_str()` 同一套清洗与小写），运行时守卫、重启后的成本回收与审计都按这同一个字符串匹配；`normalize_channel_budget_key` 把手输或库里的写法规范化且不抛错，`parse_channel_budget_key` 给写入口用，只收 `{渠道}:group:{群 ID}` 形态（私聊不会命中任何渠道预算，也就没有对应的策略） |
| `budget_day.py` | 核心 | 预算日的唯一定义：预算日是本机本地日历日（harness 的两个进程内守卫按它翻日），库里消息时间戳是朴素 UTC；`budget_day_start_utc(days_ago)` 把往前第 `days_ago` 天预算日的本地零点换成朴素 UTC（逐日换算，23 或 25 小时的夏令时日也从各自的零点起算），全局与渠道的重启成本回收和渠道审计窗口都从它起算 |
| `spend_control_service.py` | 桥接 | 提供四档渐进花费干预引擎的进程级单例 |
