# Budget Services Architecture

## 架构概述

服务端预算层：加载并持久化用户预算策略，向 Agent 工厂注入多维预算守卫，按渠道隔离配额，并桥接 harness 的四档渐进花费干预引擎。

## 文件清单

| 文件 | 地位 | 职责 |
| --- | --- | --- |
| `__init__.py` | 入口 | 包标识，不导出符号 |
| `enforcer.py` | 核心 | 预算策略读写、进程级多维预算守卫单例、执行阻断判定与会话预算重置；守卫首次建立时（含保存策略时尚无守卫）按预算日起点（`budget_day.py`）汇总库里的当日花费作为初值 |
| `channel_budget.py` | 核心 | 渠道级日预算的守卫注册表、成本记账与策略持久化，避免单个渠道耗尽全局预算；全部策略存在一行里，保存（整条替换）、局部更新（`patch_channel_budget_policy`：只改传入的字段，并入写入那一刻库里的策略，渠道不存在时返回 None 而不是新建）与删除共用同一个读改写入口：先取写锁再读（不先取锁的读改写在另一个写者先提交时会以 `database is locked` 失败），提交后紧接着（其间不 await）更新注册表，所以生效的守卫按提交顺序跟随库里的策略，当日成本在取写锁之前查好；已有守卫的渠道重配时，新守卫从旧守卫已累计的花费与这份查出的当日成本中较大的一个起算（查出的值可能比已累计的旧，读不到时为 0；没有旧守卫时直接用查出的值），所以编辑上限或开关不会让已花的数字回落；重启后每条已存策略都登记进注册表（停用的策略不建守卫、不查成本，仍按停用状态列出），启用策略的当日成本（自预算日起点，见 `budget_day.py`）按渠道键的段边界汇总（`channel_key_extends`），相邻群组不互相计入 |
| `channel_budget_policy.py` | 核心 | 渠道预算的策略模型：单条策略（渠道键一律是规范键，库里存的键不论写法，读出时同样规范化；日限额 0.01 至 10000、告警阈值 0.1 至 1.0）、局部更新体 `ChannelBudgetPolicyPatch`（四个可选字段，拒绝未知字段；并入库里的策略后按单条策略的同一套规则校验）、存库的聚合（规范键相同的多条策略合并为较严的一条——先取启用的、再取日限额低的——并记一条 WARNING） |
| `channel_budget_key.py` | 核心 | 渠道预算键的唯一定义：群组的预算键就是它的会话键去掉纪元、话题与智能体后缀（`group_budget_key`，与 `SessionKey.to_str()` 同一套清洗与小写），运行时守卫、重启后的成本回收与审计都按这同一个字符串匹配；`normalize_channel_budget_key` 把手输或库里的写法规范化且不抛错，`parse_channel_budget_key` 给写入口用，只收 `{渠道}:group:{群 ID}` 形态（私聊不会命中任何渠道预算，也就没有对应的策略）；`budget_key_of_session_key` 反过来从库里存的会话键（带纪元、话题、智能体后缀）取出它所属群组的预算键，非群组的键、没有渠道键的聊天、不成合法预算键的得到 None，所以它给出的键都能被 `parse_channel_budget_key` 原样接受 |
| `channel_budget_groups.py` | 核心 | 预算面板的群组读取侧：`list_known_group_keys` 一次查询按预算键汇总库里已有聊天的群组（同一群的多个聊天——新纪元、话题、智能体——合成一个键，活跃时间取其中最近的，最近活跃的在前）；`mark_known_groups` 给渠道状态各补一个 `known`（该群是否已有聊天，与成本回收、审计用同一个段边界匹配 `channel_key_extends`；守卫不走这个匹配，只按群消息的预算键精确查找），按键逐个探测索引、命中第一个聊天即止（一条 `OR` 要读出每个群的全部聊天，耗时随群的历史增长；逐键探测不读群的其余聊天）；探测失败时记 WARNING 并把所有渠道按「已见过」处理，数据库抖动不会让面板怀疑一个正确的键 |
| `budget_day.py` | 核心 | 预算日的唯一定义：预算日是本机本地日历日（harness 的两个进程内守卫按它翻日），库里消息时间戳是朴素 UTC；`budget_day_start_utc(days_ago)` 把往前第 `days_ago` 天预算日的本地零点换成朴素 UTC（逐日换算，23 或 25 小时的夏令时日也从各自的零点起算），全局与渠道的重启成本回收和渠道审计窗口都从它起算 |
| `spend_control_service.py` | 桥接 | 提供四档渐进花费干预引擎的进程级单例 |
