# rendering/

## Overview
Outbound message formatting: Markdown/plaintext rendering, message splitting, and cost metadata footer.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Outbound message formatting: Markdown/plaintext rendering and message splitting. | — |
| converter_registry.py | Core | Pluggable format conversion registry. Channels register (source_format, | ✅ |
| renderer.py | Core | Outbound message formatting pipeline (_prepare → _format → split_message). Full body content flows to split_message for multi-chunk IM delivery, counted in the style's `length_unit`. A reply is rendered once: `mark_rendered()` stamps a message that carries one rendered chunk (tool summary, sources and header already in its text), and `render()` returns such a message as `[content]`, so a channel that renders what it receives cannot decorate it a second time. `is_rendered()` answers the same question for a channel that builds its own decoration from message metadata (the Feishu card) instead of calling `render()`. A collapsed reasoning is a Markdown quote; only a style with `supports_expandable_blockquote` (Telegram's plain style) gets the HTML `<blockquote expandable>`, which every other channel would show as literal tags. | ✅ |
| splitter.py | Core | Smart long-message splitter + `cap_stream_preview` for streaming IM placeholders. Fence state machine (fence lines are read as CommonMark does: any info string such as `c++` or `python title=demo`; a block ends only at a bare fence of the same character at least as long as its opener, so any other fence-like line inside a block is code), CJK boundaries, join-preserving line iteration; `fenced_block_at` names the code block a cut would split (where it starts and where it ends) under the same fence rules, so another splitter can keep a block whole; no chunk is longer than `max_len` (a code line too long for a chunk is cut and fenced piece by piece) and splitting never leaves a chunk holding only a fence marker. `max_len` is counted in the unit the caller names (`LengthUnit`: characters by default, or UTF-8 bytes for a platform that limits bytes; byte cost per character, a lone surrogate counts three, a character dearer than the limit goes out alone). | ✅ |
| text_utils.py | Core | Universal text utilities. Provides code-block-aware text processing and the fenced block → `<pre>` rendering that Telegram and Matrix share (`FENCED_BLOCK_RE`, `fenced_block_html`): the info string is free text such as `c++` or `python title=demo` and its first word names the language; a fence that follows text on its line carries only a word, so prose mentioning ``` opens no block; a block ends at the run of backticks (3–10) that opened it, so one fenced by four shows the three-backtick blocks it documents. The code-aware helpers (`extract_safe_regions`, `with_protected_code_blocks`, `md_to_plaintext`) use the same run rule, so they treat such a block as one piece of code. | ✅ |
