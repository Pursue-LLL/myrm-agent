# core/

## Overview
Core infrastructure: BaseChannel, MessageBus, ChannelGateway, EventEmitter, Credentials, Mixins.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Core infrastructure: BaseChannel, MessageBus, ChannelGateway, EventEmitter, Credentials, Mixins. | — |
| allow_policy.py | Core | Inbound access control policy. ChatPolicy, FilterReason, ChatPolicyOverride, AllowPolicy with bot_policy and per-chat overrides. | ✅ |
| attachment_delivery.py | Core | Per-attachment delivery shared by providers: `attempt_attachments` tries every attachment without letting one failure block the others; `deliver_attachments` returns the last id the platform reported and raises one `ChannelSendError.for_attachments` naming what did not arrive (partial delivery when anything already reached the recipient, non-retriable only when every failure is permanent). | ✅ |
| base.py | Core | Channel abstraction layer. All providers inherit this class; Gateway manages them uniformly. Optional hook `read_context_document()` (default: none): a provider that can read the document a message is about overrides it, and the router attaches the result to the turn. `edit_message` / `edit_placeholder_message` of a channel with `capabilities.edit` raise `ChannelSendError` when the platform did not apply the edit; the router and the bus send a new message only on that signal. `BaseChannel` inherits `InboundPipelineMixin`, `ReplyShortcutsMixin` and `ProviderHooksMixin`; each moved method is the same code, so provider overrides and `super()` calls behave as before. | ✅ |
| bus.py | Core | Message routing hub and state holder: queues, channel registry, durable publish (IM channels persist via DurableOutboundGate before dispatch), inbound handoff and DLQ admin. The dispatch loop is spawned via `spawn_observed_task` (a real death is logged with a stack), and `is_dispatch_loop_alive` / `ensure_dispatch_loop_alive` expose liveness for the Gateway's supervision. The delivery pipeline lives in `OutboundDispatchMixin`; an in-flight counter tells `drain_outbound` an idle bus from one with a send under way. `edit_channel_message` reports True only when the platform applied the edit; a channel without `capabilities.edit` is not asked. | ✅ |
| credentials.py | Core | Framework-level credential type definitions and generic parser. Providers declare | ✅ |
| events.py | Core | Channel event infrastructure. Channels emit events (status changes, group updates), | ✅ |
| exceptions.py | Core | Channel exception hierarchy for precise retry and error handling. `ChannelSendError.accepted/failed_attachments` mark partial delivery (`for_attachments` builds it); `ChannelSendError.from_http_status` classifies an HTTP rejection (408/425/429/5xx retriable, other 4xx permanent); `DeliveryUnconfirmedError` marks a send the channel did not prove. | ✅ |
| factory.py | Core | Framework-level channel factory. Decouples credential resolution from channel instantiation; skips invalid credentials (`ValueError`) without stack traces. | ✅ |
| gateway.py | Core | Channel system entry point. Manages all channel lifecycles, health checks, error isolation, and inbound crash recovery via InboundJournal. The health loop supervises both long-lived loops that must stay alive: the router's consume loop and the bus outbound dispatch loop. A finished task (each loop absorbs per-message errors, so a finished task means it died) is restarted with exponential backoff, so neither inbound routing nor outbound delivery can stay silently down while the process looks healthy. Channel checks iterate a snapshot of the channel dict, so a concurrent credential swap cannot abort the round. `enable_channel` triggers durable outbound recovery. Accepts extra_commands for business-layer command injection and skill_command_handler for skill-bound slash commands. `update_skill_commands()` enables runtime hot-reload of SKILL-type command bindings without restart. `swap_channel()` is the single atomic instance-replacement primitive (remove old → add new → restore old on failure) shared by all credential hot-reload paths. `stop()` stops the router first, then waits (bounded by `_SHUTDOWN_OUTBOUND_DRAIN_SECONDS`) for the outbound queue the router just filled (a delegated task's interruption notice) before the channels and the bus close. `deliver_followup(origin, content, media=())` hands the router a reply (with its attachments) no message just asked for and returns whether it was sent (`False` without a router; the ephemeral temp attachments of a reply that is not delivered are deleted). `is_session_busy(origin)` says whether the router is running a turn for the conversation `origin` came from (`False` without a router). | ✅ |
| inbound_pipeline.py | Core | `InboundPipelineMixin`: the inbound pipeline of every channel (`_build_inbound`, `_emit_inbound`: DISABLED and self-message filter, dedup by `DedupMode`, rate limit, access policy, debounce, dispatch to the registered `InboundHandler`). The dedup cache, debounce buffers and handler are created by `BaseChannel.__init__`; this module owns the stages and the dedup/debounce settings. | ✅ |
| mixins.py | Core | Reusable channel capability components via Mixin pattern. Allows different channels | ✅ |
| outbound_attachment_guard.py | Core | Last-hop guard against exfiltrating key material: `withhold_sensitive_attachments` removes local attachments that look like keys or credentials (harness `is_sensitive_file`, symlink target included, `.key` released only for Keynote ZIPs; ephemeral temp files and URLs are not inspected) and names them in a localized note. Name-based seatbelt, not a classifier. | ✅ |
| outbound_dispatch.py | Core | Delivery half of MessageBus. Priority dispatch loop and direct send share one route resolution (control-plane egress first), one preparation step and one settle step. Each dequeued message is routed by `_dispatch_one` inside a per-message `try/except Exception`: one poisoned message is logged and settled as a failed send (record acked, payload kept for manual retry) instead of killing delivery for every channel or being re-injected by disk recovery. `send_now` raises unless delivery is proven; `send_tracked` is its lenient wrapper. Partial delivery is recorded per attachment, never replayed whole. Retains the disk obligation when the channel is disabled/stopped/unregistered, and `can_deliver` tells durable recovery which records are worth re-injecting so an undeliverable one cannot spin the idle poll. Owns `ephemeral` temp attachments after hand-off: deleted once delivery is final (acked, or dropped with no disk record), kept while a DLQ/durable record still references them. `drain_outbound(timeout)` waits until the queue is empty and nothing is mid-send, and gives up at the timeout or when the dispatch loop is not running, so a shutdown flushes what was just published without hanging on an unreachable channel. | ✅ |
| outbound_failure.py | Core | Failure half of MessageBus. DLQ persistence, permanent-failure callback, notification dedup and DLQ threshold alert for failed outbound sends. | ✅ |
| outbound_gate.py | Core | Pre-publish outbound content & link liveness gate. Probes extracted URLs concurrently via fast HTTP HEAD/Range with TTL cache and annotates dead links with a soft warning; never withholds a message. `probe_url` never raises (any non-cancellation probe failure settles as unreachable), so a URL the HTTP client rejects cannot abort message delivery in the dispatch loop. | ✅ |
| outbound_media.py | Core | Lifecycle of temporary attachment files: `discard_ephemeral_media` deletes `ephemeral` attachments (inside the system temp dir only) except paths a failure record still references. | ✅ |
| outbound_prepare.py | Core | Pure outbound transformations shared by every send path: correlation lineage, `prepare_outbound` (sensitive-attachment guard, capability-based component/media downgrade, then outbound risk gate), delivery verdict (`delivery_unconfirmed`), partial-delivery remainder and localized attachment notes. | ✅ |
| provider_hooks.py | Core | `ProviderHooksMixin`: optional hooks with a safe default that a provider overrides when its platform has the capability — `register_routes`, `_get_route_prefix`, `start_login` / `cancel_login` / `handle_oauth2_callback`, `fetch_history`, `read_context_document`. | ✅ |
| rate_limit.py | Core | Rate limiting for inbound messages. | ✅ |
| reaction_ledger.py | Core | `ReactionLedger`: bounded memory of the reaction handle (name, glyph, Tapback name, Teams reaction ID or reaction event id) a channel added per `(chat_id, message_id)`, so `react_to_message("")` removes exactly what it added and makes no call when it added nothing. | ✅ |
| reply_shortcuts.py | Core | `ReplyShortcutsMixin`: `respond` (reply to an inbound message, channel/recipient/user/reply target inferred) and `broadcast` (proactive message, explicit `user_id`), both thin wrappers over `send`. | ✅ |
| user_resolver.py | Core | Generic user resolver protocol and cache implementation. Protocol-first framework design | ✅ |
