# routing/pipeline/

## Overview

The behavior of `AgentRouter` in the order a message meets it: run loop, inbound routing, command dispatch, the turn, execution, and delivery. `router.py` keeps construction and the state the stages share; `hosts.py` types what each stage reads from the router instance. Parent: [../_ARCH.md](../_ARCH.md).

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| `__init__.py` | Facade | Re-exports the six mixins `AgentRouter` is composed from. | [OK] |
| `hosts.py` | Core | Typing protocols (`RouterLifecycleHost`, `RouterInboundHost`, `RouterCommandDispatchHost`, `RouterTurnHost`, `RouterExecutionHost`, `RouterDeliveryHost`): the host attributes and cross-mixin methods each stage uses, so a mixin type-checks without importing the router. `AgentRouter` satisfies every protocol structurally. | [OK] |
| `lifecycle.py` | Core | `RouterLifecycleMixin`: `start` (also the restart entry point once the consume task has finished), `stop` (parks the messages the gate holds that have not started a turn in the inbound journal, interrupts the delegated tasks, each tells its chat while the channels are still up, then cancels the in-flight turns, clears the approvals and tells the chat of each cancelled turn to send the request again, since a cancelled turn is not replayed; the notice replaces the turn's live placeholder message, or is a new message when there is none, the same way the stuck-task reaper tells its chat; the notices go out together and each send is bounded by `_NOTICE_SEND_TIMEOUT`, in the stop and in the reaper alike), the consume loop (one dispatch per message; a handler error is logged and the loop keeps consuming), the janitor sweep (expired callbacks, streaming-session TTL, stale session state) and the stuck-task reaper (it frees the `SessionGate` turn recorded on the stuck task). See *Consume-Loop Resilience* and *Stuck Task Watchdog* in [../_ARCH.md](../_ARCH.md). | [OK] |
| `inbound.py` | Core | `RouterInboundMixin._dispatch_inbound_message` is the sequence of named steps one message passes, each claiming it (the dispatch ends) or leaving it for the next: dedup, `_note_group_activity`, locale enrichment, `_claim_approval_input` (action-button click, reaction, typed approval word; a reaction never becomes a turn), `_claim_command` (slash registry, raw shell command), `_fire_event_triggers` (never claims), `_claim_delegation`, `_claim_delegated_task_steering`, `_divert_group_chatter` (group text that arrives while the chat's turn runs and is not addressed to the bot is settled the way an idle chat settles it: held by the risk gate, else recorded as context for the next turn; it is neither queued nor acknowledged as queued; attachments, answers and an error in the check keep the normal path), then `SessionGate.submit`. Text typed while a turn runs is never taken into that turn here: it waits for the gate as a turn of its own, and `/steer` (a system command, screened once in `_dispatch_resolved`) is the way into the running one. The inbound risk gate (`hold_risky_inbound`; symmetric with the outbound risk gate in bus.py) screens the text on the paths that reach an agent without a turn of its own: the delegation prompt, the in-flight delegation steering, group text kept as context while the chat's turn runs (`_divert_group_chatter`) and, in `_dispatch_resolved`, the arguments of system commands. `_fire_event_triggers` dispatches cron event triggers via `inbound_event_dispatch` (only for senders the access policy admits, `_is_sender_admitted`, fail-closed; the dispatch screens the text with `screen_user_text` first, so a held message starts no job; the turn path of that message records the hit and tells the sender, the dispatch only detects; the job runs under the untrusted-ingress fence when `_is_untrusted_event_sender`, fail-closed). `_reply_in_background` answers the sender from a task. `_check_admin_permission`, `_is_sender_admitted` and `_is_untrusted_event_sender` all fail closed; `_is_duplicate` is the TTL dedup keyed by channel and message id. | [OK] |
| `command_dispatch.py` | Core | `RouterCommandDispatchMixin._dispatch_resolved`: owner-only check, then the arguments of system commands go through `hold_risky_inbound` (commands that act on their text directly: a background task, a goal, a kanban card, a steer; agent-route and skill commands are screened on the agent path they reach); `_dispatch_system_command` maps the action to the handler in `commands/`. Also the `!shell` migration reply, skill-bound commands and `/help`. | [OK] |
| `turn.py` | Core | `RouterTurnMixin._handle_merged`, the `SessionGate` `on_ready` entry, runs these steps in order: `_journal_inbound` writes the inbound journal entry (a replay has its entries already, one for each replay merged into the turn, so nothing is written); `_apply_session_state` applies the channel capabilities and the session's yolo and personality state; `_enrich_attachments` enriches attachments (voice and video transcripts are merged into `msg.content`; document text rides in `metadata.document_text_blocks` and images in `metadata.image_data_list`; a sender the access policy refuses, per `PolicyResolver.is_sender_admitted`, gets none of it and the message goes on as it came, while an error in that check processes the attachments anyway); the inbound risk gate screens the turn text (transcripts are screened with it, document text and images are not; a long paste reaches the turn whole, the persistence layer parks it where the agent can read it back); `_apply_agent_route` rewrites an agent-route alias (an alias alone binds the chat and ends the turn); then the turn is prepared and executed under the concurrency semaphore, and `_report_turn_failure` is the error path (placeholder turned into the error text, error reply, then the failure reaction: the words come first). The turn owns the status reaction of its message (`reactions/status.py`): it marks the message before the run and settles the mark once, as completed, failed or abandoned (a stopped turn only has its mark taken off). A held turn acknowledges its inbound journal entries before returning (every early return does, via `_acknowledge_inbound`). A plain turn that starts in the agent session of an open approval retires that approval first (`_retire_open_approval`). The turn ends for the `SessionGate` when `_handle_merged` returns; the handler never signals the gate itself. | [OK] |
| `execution.py` | Core | `RouterExecutionMixin` builds on `RouterDeliveryMixin` (`delivery.py`: effects, reply delivery, draft review hold, cleanup); `_prepare_execution_context` rejects search-track `route_agent_id` (external CLI aliases like `claude` unchanged); `_execute_prepared_context` runs `enrich_context_document` on a non-resume turn right before the executor stream and passes a resumed run its topic context only through `resume_topic_context`. It registers the run in `_active_tasks` with the gate session (`gate_key(exec_msg)`) and turn it runs as, which the watchdog releases. `deliver_followup(origin, content, media=())` is the one way to say something (with attachments) in a conversation that no message just asked for (the reply of a wake turn): it resolves the topic of `origin`, gives nothing to a topic disabled since (and deletes the ephemeral temp attachments it was handed), and hands the text to `_deliver_agent_result` without a placeholder, so the silent-reply filter, the web hand-off button and draft review hold apply as they do to the answer of a message. `is_session_busy(origin)` asks the session gate whether a turn of that conversation is running, so a message said there now would queue behind it (a wake turn waits for it). | [OK] |
| `delivery.py` | Core | `RouterDeliveryMixin`: `_setup_message_effects` (deferred placeholder, typing, cleanup registration; the status reaction is the turn's, not set here); `_deliver_agent_result` auto-attaches the WebUI handoff deep-link button for IM channel replies and intercepts the whole outbound reply (attachments and buttons included) as a draft ApprovalRecord when `topic_ctx.reply_mode == "draft_review"` (Channel Outbound HITL), and a reply that cannot be held is withheld (fail-closed), never sent unreviewed; `_cleanup_effects` ends the turn's registration and typing (it leaves the status reaction to the turn) and keeps the `_active_tasks` entry while an approval is pending, so numeric shortcut replies reach the approval handler; `_register_cleanup` registers the TTL janitor closure. `RouterExecutionMixin` builds on it. | [OK] |

## Dependencies

`hosts.py` imports only types. The mixins import the `commands/` facade (parsers), `router_models`, `router_constants`, `router_keys`, `inbound_risk_gate` and the channel media/voice enrichers; none imports `router.py`, so the package can be imported before the router.
