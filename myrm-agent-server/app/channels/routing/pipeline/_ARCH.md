# routing/pipeline/

## Overview

The behavior of `AgentRouter` in the order a message meets it: run loop, inbound routing, command dispatch, the turn, execution, and delivery. `router.py` keeps construction and the state the stages share; `hosts.py` types what each stage reads from the router instance. Parent: [../_ARCH.md](../_ARCH.md).

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| `__init__.py` | Facade | Re-exports the six mixins `AgentRouter` is composed from. | [OK] |
| `hosts.py` | Core | Typing protocols (`RouterLifecycleHost`, `RouterInboundHost`, `RouterCommandDispatchHost`, `RouterTurnHost`, `RouterExecutionHost`, `RouterDeliveryHost`): the host attributes and cross-mixin methods each stage uses, so a mixin type-checks without importing the router. `AgentRouter` satisfies every protocol structurally. | [OK] |
| `lifecycle.py` | Core | `RouterLifecycleMixin`: `start` (also the restart entry point once the consume task has finished), `stop` (interrupts the delegated tasks first, each tells its chat while the channels are still up, then cancels the in-flight turns and clears the approvals), the consume loop (one dispatch per message; a handler error is logged and the loop keeps consuming), the janitor sweep (expired callbacks, streaming-session TTL, stale session state) and the stuck-task reaper. See *Consume-Loop Resilience* and *Stuck Task Watchdog* in [../_ARCH.md](../_ARCH.md). | [OK] |
| `inbound.py` | Core | `RouterInboundMixin._dispatch_inbound_message`: after dedup, locale enrichment and approval/reaction/slash filtering, checks active task `busy_input_mode` (steer/redirect auto-dispatch; only a task that is still running is steered, a finished entry that stays registered to keep its approval answerable is not), applies the inbound risk gate (`hold_risky_inbound`; symmetric with the outbound risk gate in bus.py) to the busy steer/redirect, delegation prompt and in-flight delegation steering paths, dispatches cron event triggers via `inbound_event_dispatch` (only for senders the access policy admits, `_is_sender_admitted`, fail-closed; the dispatch screens the text with `screen_user_text` first, so a held message starts no job; the turn path of that message records the hit and tells the sender, the dispatch only detects; the job runs under the untrusted-ingress fence when `_is_untrusted_event_sender`, fail-closed) and then submits to SessionGate. `_check_admin_permission`, `_is_sender_admitted` and `_is_untrusted_event_sender` all fail closed; `_is_duplicate` is the TTL dedup keyed by channel and message id. | [OK] |
| `command_dispatch.py` | Core | `RouterCommandDispatchMixin._dispatch_resolved`: owner-only check, then the arguments of system commands go through `hold_risky_inbound` (commands that act on their text directly: a background task, a goal, a kanban card, a steer; agent-route and skill commands are screened on the agent path they reach); `_dispatch_system_command` maps the action to the handler in `commands/`. Also the `!shell` migration reply, skill-bound commands and `/help`. | [OK] |
| `turn.py` | Core | `RouterTurnMixin._handle_merged`, the `SessionGate` `on_ready` entry: writes the inbound journal entry, applies the session's yolo and personality state, enriches attachments (voice and video transcripts are merged into `msg.content`; document text rides in `metadata.document_text_blocks` and images in `metadata.image_data_list`), applies the inbound risk gate to the turn text (transcripts are screened with it, document text and images are not; a long paste reaches the turn whole, the persistence layer parks it where the agent can read it back), rewrites an agent-route alias, then prepares and executes the turn under the concurrency semaphore. A held turn acknowledges its inbound journal entry before returning (every early return does, via `_acknowledge_inbound`). A plain turn that starts in the agent session of an open approval retires that approval first (`_retire_open_approval`). | [OK] |
| `execution.py` | Core | `RouterExecutionMixin` builds on `RouterDeliveryMixin` (`delivery.py`: effects, reply delivery, draft review hold, cleanup); `_prepare_execution_context` rejects search-track `route_agent_id` (external CLI aliases like `claude` unchanged); `_execute_prepared_context` runs `enrich_context_document` on a non-resume turn right before the executor stream and passes a resumed run its topic context only through `resume_topic_context`. | [OK] |
| `delivery.py` | Core | `RouterDeliveryMixin`: `_setup_message_effects` (reaction, deferred placeholder, typing, cleanup registration); `_deliver_agent_result` auto-attaches the WebUI handoff deep-link button for IM channel replies and intercepts the whole outbound reply (attachments and buttons included) as a draft ApprovalRecord when `topic_ctx.reply_mode == "draft_review"` (Channel Outbound HITL), and a reply that cannot be held is withheld (fail-closed), never sent unreviewed; `_cleanup_effects` keeps the `_active_tasks` entry while an approval is pending, so numeric shortcut replies reach the approval handler; `_register_cleanup` registers the TTL janitor closure. `RouterExecutionMixin` builds on it. | [OK] |

## Dependencies

`hosts.py` imports only types. The mixins import the `commands/` facade (parsers), `router_models`, `router_constants`, `router_keys`, `inbound_risk_gate` and the channel media/voice enrichers; none imports `router.py`, so the package can be imported before the router.
