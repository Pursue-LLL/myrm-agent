# workspace_rules/

## Overview
Workspace rules — project-level context file discovery and injection.

Two-layer mechanism:
1. **Workspace context injection** (`middleware.py`): On every model call, reads the workspace rules live and injects them, with the sandbox snapshot, as one SystemMessage after `user_instructions`, before `memory_context`; a rule file whose text has not changed is read and sanitised again but not scanned for injection again. One scan reads through one `RuleReadGuard`: a file whose real path leaves the git root (the workspace root when there is none) is not read, and a scan reads at most 512 files, 2,000,000 characters and 256,000 characters of one file; rule file names reach the prompt as single-line plain text. The snapshot is taken once per chat thread, by the first model call that finds none (in a worker thread under a 3 s deadline, so neither the event loop nor a hung probe holds the call for long), and handed to private checkpointed state with that call's response; a probe that outruns the deadline is abandoned and the thread keeps an empty snapshot; no hook node runs per model call.
2. **Progressive discovery** (`tracker.py`): Monitors tool call arguments for directory paths, discovers rules in newly accessed subdirectories, appends to tool results.

## File & Submodule Index

| File | Role | Description | I/O/P |

| __init__.py | Package | Public API exports for workspace rules module. | — |
| adr_scanner.py | Core | Architectural Decision Record (ADR) scanner. Discovers MADR format decisions under docs/decisions/ and filters by status (keeps accepted/active, filters out deprecated/superseded); each record is read once, through the scan's `RuleReadGuard`, and the status test runs on that text. | ✅ |
| content_safety.py | Core | Injection verdict for one rule file's text: an unambiguous `scan_input` block score ≥ 0.8 blocks, suspicious patterns only log a warning. The verdict is remembered per blake2b digest of the text (`LRUCache`, 2048 entries, one-day lifetime, access serialised by a lock), so an unchanged file is scanned once per process, an edited file on the next call, the same text under another path shares the verdict, and the warning is written when the text is scanned. The capacity is well above the number of rule files one scan reads, because an LRU walked in order by a longer scan never hits (the verdicts stay correct, only the saving is lost). | ✅ |
| rule_read_guard.py | Core | Boundary and budgets of one rule scan. `RuleReadGuard(boundary).read(path)` refuses a file whose real path (`is_within_boundary`, symlinks resolved) is outside the boundary, stops reading after 512 files (every file asked about counts, a refused one too) or 2,000,000 characters, and reads a file through `core.security.path.read_text_bounded` in text mode up to 256,000 characters (`read(limit + 1)`, so a file over the limit is refused without being read whole and a file within it is exactly what `Path.read_text` returns, line endings included); a candidate that is not a regular file (a FIFO, a device) is skipped without a read, a wait or a note. A refusal is returned as a reason (`RuleRead.refusal`) that the caller shows as a placeholder; only the first three refusals of a scan carry one. A scan runs on every model call, so a refusal, and a scan that runs out of budget, are each a warning the first time this process sees them (up to 256 events are remembered, and the memory starts again when it is full) and a debug line after that. The limits are at least twice the largest scan measured over 293 open-source repositories (159 files, 114,618 characters in one file, 377,804 characters in all). The character budget is checked before each read, so the last read can pass it by one file (at most 256,001 characters). | ✅ |
| scanner.py | Core | Rule file discovery, the injection verdict (`content_safety.py`), YAML frontmatter stripping, and loading. Uses First-Match-Wins priority loading per directory to prevent conflicts (e.g., .myrm.md > SOUL.md > MEMORY.md > AGENTS.md > .cursorrules). Supports AGENTS.md, CLAUDE.md, SOUL.md, MEMORY.md, KNOWN_ISSUES.md, docs/decisions/*.md, .cursorrules, .clinerules, .myrm.md, .hermes.md, HERMES.md, .windsurfrules, .myrm/rules/*.md, .cursor/rules/*.mdc, .claude/CLAUDE.md, .github/copilot-instructions.md. Traverses upward to git root (max 5 levels; without a git root the walk stops at the resolved workspace root, whether or not the path given was resolved). inode-level dedup for case-insensitive filesystems. Head/tail truncation for large files. Blocked files (injection detected: unambiguous `block_score` ≥ 0.8, so ordinary role/mode phrasing does not block; outside the boundary; over the read limit) return a `[BLOCKED]` placeholder RuleFile with `blocked=True` instead of being silently skipped. `RuleFile.display_name` is the file name as single-line plain text (`core/security/detection/display_name.py`), used by the placeholder, the truncation marker, the system message block heading and the tracker. | ✅ |
| middleware.py | Core | AgentMiddleware for workspace context injection. Injects discovered rules and lightweight sandbox environment bootstrap snapshot (working dir, entries, runtimes, package managers) as SystemMessage at KV Cache-optimal position (after user_instructions, before memory_context). Rules are read live on every call; the snapshot is taken once per chat thread by the first model call that finds none (off the event loop, under a 3 s deadline; stored with that call's `ExtendedModelResponse` in `workspace_snapshot`, `workspace_snapshot_root` in private state, retaken when the workspace changes; a call whose model request fails stores nothing; a probe that outruns the deadline is abandoned and an empty snapshot is stored, so the thread neither probes again nor gets a snapshot block), so the text at this position does not move while the agent edits files and no graph step or checkpoint is added to a model call. A workspace the trust gate blocks is neither probed nor injected. | ✅ |
| tracker.py | Core | SubdirectoryContextTracker for progressive rule discovery. Session-scoped via ContextVar. Extracts directory paths from tool call arguments, checks for rule files, appends content to tool results (not system prompt). Enforces 16000 char budget with explicit truncation to prevent silent dropping. One `RuleReadGuard` serves the rule files read for one tool result (boundary: the workspace root). Integrated via tool_interceptor_middleware POST-CALL stage. | ✅ |
