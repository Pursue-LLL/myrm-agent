# diagnostics/

## Overview
Error diagnostics component. Provides LLM error classification, context extraction, and structured diagnostic results.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Error diagnostics — data types (ErrorContext, DiagnosticResult) and re-exports. | ✅ |
| engine.py | Core | LLMErrorDiagnostic — error classification engine: tries the transport and account families first (connection, tls_certificate, custom_endpoint_unreachable, billing, api_key), then model / custom_model_not_found, rate_limit, response_format_error, context_overflow, timeout, then every failure the shared classifier recognizes that those families did not catch (api_key, billing, rate_limit, timeout, context_overflow, response_format_error, overloaded, safety_block, format_error, challenge_blocked), and unknown last. A missing model and a subscription tier gate are left out of that bridge: the classifier files provider policy blocks under the first and the tier gate under context overflow, and the provider's own words explain both better. The `unknown` and `format_error` messages carry the provider's own wording: read from the exception's payload first (`errors/error_payload.py`: an aggregator's upstream error before its wrapper, escapes decoded by the JSON decoder), else from the exception text (library prefixes stripped, the body's `message` field, an HTML error page reduced to its visible text), then tidied by `_present`: credentials masked before the text is cut to 200 characters, an ellipsis marking a cut. A `format_error` whose exception carries no provider payload (a failure the client library raised before any request) quotes nothing: it names the request's model when the caller's `ErrorContext` carries one (`format_error_model`), else it states the failure plainly (`format_error_generic`); `unknown` falls back to the exception's own text. Text that is only a rendering of data (a JSON object or array with no sentence in it) is never quoted: `format_error` falls back to the model or generic wording and `unknown` names the exception class. Also the truncation diagnostics (thinking_budget_exhausted, tool_call_truncated, tool_call_retry, text_continuation, text_continuation_exhausted) + provider-stated wait hint (rendered by `cooldown_hint.py`); the rate-limit diagnosis words the wait once: the generic `rate_limit_wait_step` leads `resolution_steps` only when the provider stated no wait, so the message and the steps never name two different waits + `get_recovery_actions` facade over recovery_actions.py. | ✅ |
| transport_diagnosis.py | Core | `diagnose_transport` — TLS (tls_certificate for rejected or strict-mode certificates, tls_transient for an interrupted handshake) and connection (connection, custom_endpoint_unreachable) families; `infer_service_name` and `extract_port` read the local service and port out of a custom endpoint URL (also used by the model-not-found diagnosis). | ✅ |
| account_diagnosis.py | Core | `diagnose_account` — billing, opencode_training_policy (provider policy rejecting the request) and api_key families. | ✅ |
| catalog_result.py | Core | `build_catalog_result` — the single assembler from an error type to a localized `DiagnosticResult` (message, steps, provider wait appended to the message); transport, account and engine families name the error and leave the wording to the catalogue; `entry` selects a wording variant of the same error type (the result keeps the type consumers act on). | ✅ |
| cooldown_hint.py | Core | `format_cooldown_hint` — renders the provider's wait in the caller's language from the `cooldown_hint_*` locale keys (template, unit words in singular/plural, and the joiner between two units). Below an hour the wait stays in seconds, the unit the provider reports it in; from an hour up it is spelled in its two largest units with the smaller one rounded up (`6 hours 24 minutes`, `7 days`). A bundle without the unit words of such a wait states it in its own seconds, and a missing bundle falls back to an English sentence in seconds. | ✅ |
| recovery_actions.py | Core | build_recovery_actions — recovery button catalogue: error types with a single-click fix (api_key, billing, model, custom_model_not_found) map to localized {id, label, url} actions; key and model buttons land on `/settings/models`, top-up on `/settings`; other error types have none. | ✅ |
| types.py | Core | ErrorContext and DiagnosticResult (error_type, user_message, resolution_steps, locale) frozen dataclasses for structured LLM error diagnosis. | ✅ |
