| progress_payload.py | Core | Shared notify/progress field SSOT (`parse_ptc_notify_params`, `build_workflow_stage_event`, `build_ptc_notify_payload`). Used by PTC `notify_handler` and DW `NotifyProgressTool`. | ✅ |
| notify_registry.py | Core | Session→RunnableConfig registry (with `session_scope` async ctx mgr) so the IPC task can resolve the caller's config for `notify` dispatch. | ✅ |
| client_templates.py | Core | Provides MCPError, generate_ipc_client_code. Injects `_AUTH_TOKEN` / `_TRACE_NONCE` into the in-script IPC client; a request carries the call and the token only, because session, agent, workspace and read-only state belong to the server (`CallerScope`) and a script cannot restate them. Emits call markers as `__MCP_DATA__{nonce}{base64(json)}__END__{nonce}` (marker shape is defined once in `toolkits/code_execution/executors/common/mcp_markers.py`). The generated `_SkillFunction` proxy is keyword-only and rejects positional calls with an actionable TypeError. | ✅ |
| core_generator.py | Core | MCP Skill Generator — orchestration for MCP-to-Skill conversion. Connects to all MCP servers in parallel (`asyncio.gather`), serializes configs via `mcp_config_to_runtime_dict` SSOT, reads tools + instructions from warm pooled connections, persists MCP `outputSchema` from tool metadata into `MCPSkillData.tool_schemas`, assembles L2 from `doc_rendering` under a dynamic single-server ceiling (8,000 tokens with signatures, 3,000 name-only), emits the async/await contract, resolves L1 descriptions via `description`, and generates L3 tool docs. Colliding server names are disambiguated (`_2`) so no server is dropped; L1 descriptions are scanned for high-risk findings. Sets `MCPSkillData.inline_functions` (the Python names the L1 catalog may list, from `build_tool_name_map`; empty when the server ships instructions, because only the L2 document carries them), and builds `SKILL_USAGE_TEMPLATE` from `agent/skills/runtime/ptc_calling.py`, the same calling convention the L1 rule block gives. | ✅ |
| doc_rendering.py | Core | Pure L2 rendering layer: two tier ceilings (`L2_SIGNATURE_MAX_TOKENS` 8,000 for the `full`/`required` tiers, `L2_NAMES_MAX_TOKENS` 3,000 for the `names` tier, whose tail is dropped instead of growing the prompt), instructions cap (2,000), dynamic fixed-prefix measurement, tier-note reserve (96), `instructions_token_cap` sized against the name-only ceiling so the tool section keeps its 680 floor in every tier, `tool_section_budget` returning a `ToolSectionBudget(signatures, names)`, `full → required → names` degradation chosen by token budget (not tool count), `l2_ceiling(tier)`, optional compact recursive return types from MCP `outputSchema` (full if it fits; otherwise `-> ?` plus the L3 pointer, never a truncated fake shape), `cap_instructions`, and shared text helpers (`truncate_to_sentence` / `clean_markdown` / `text_field`). `build_tool_section` requires an explicit budget so no caller can silently ignore instructions. | ✅ |
| description.py | Core | Pure L1 description policy: `resolve_description` (user description > instructions first sentence > tool summary) and `build_description_from_tools` (up to three tool descriptions, `and N more` suffix). | ✅ |
| executor.py | Core | Provides SkillExecutionContext, SkillExecutor. Resolves MCP skills via `skill_registry.get_mcp_skill_for_ipc` and builds the generated client code from the execution's `IPCEndpoint`. Prepares two kinds of code: inline Python (`prepare_for_execution`, any skill or builtin import form) and a saved script the host read (`prepare_script_for_execution`: the source, with bare skill imports given their `skills.` prefix like inline code, runs through `SavedScript.launcher` behind the client). `detect_skill_in_script` is stricter than inline detection: AST only, and only skills the host serves (registered with an MCP config), so a project's own `xxx_skill` or `tools` module and builtin imports stay plain scripts. `SkillExecutionContext.user_code` is the part of the prepared code after the client (the model's program, or the launcher that runs a saved script): the wrapper compiles it as a program of its own, and the bash tool's syntax pre-check validates exactly that text. | ✅ |
| call_backstop.py | Core | `call_within_backstop`: outer time bound for one script tool call, `max(execute_timeout of the skill's servers) + BACKSTOP_MARGIN_SECONDS` (10 s). The session actor already ends a call at the server's `execute_timeout` and answers with a failure; the backstop only covers an actor that never answers, so the script gets a named `TimeoutError` instead of waiting for the host's kill. It wraps the call alone, never the connect phase (a cold server start has its own budget). Layering: actor = limit, backstop = limit + 10 s, host kill = limit + 30 s (`bash/_executor/constants.MCP_HOST_MARGIN_SECONDS`). | ✅ |
| ipc_call_budget.py | Core | `CallBudget`: admission control of the MCP IPC server. A per-execution budget keyed by the id the server minted for its execution (`DEFAULT_MAX_CALLS_PER_EXECUTION`, 50; a rejected call is not charged) plus a loose per-session backstop (`DEFAULT_SESSION_CALL_CEILING`, 500 calls per 600 s) that bounds the scripts of one chat together. Bookkeeping tables are LRU-bounded. | ✅ |
| ipc_endpoint.py | Core | `mcp_ipc_endpoint(scope)`: async context manager that serves one script execution. Starts a server on the running loop at a fresh private socket path and stops it when the execution ends, however it ends. Start and stop are shielded from cancellation (a start cancelled after the listener is bound still gets stopped). Owns the process-wide `CallBudget`, so the per-session ceiling adds up across the scripts of one chat. | ✅ |
| ipc_proxy.py | Core | Wire types and the server: `CallerScope` (whom a server's calls are for: session, agent, workspace, read-only state, whether the run is a saved script, fixed by the host when the server starts), `IPCEndpoint` (how the generated client reaches and authenticates to one server), `MCPIPCRequest/Response`, `MCPIPCServer`, and `IPCCallContext` + `get_ipc_call_context` (ContextVar) so builtin handlers can read per-call session metadata. A request cannot name its own scope: fields beyond the call and the token are ignored, so a script cannot lift its read-only or saved-script state, widen its workspace, borrow another agent's gate or re-key its budgets. Mints `auth_token` (bearer, checked constant-time) and `trace_nonce` (marker authentication). `stop()` is idempotent, cancels in-flight connections and works on a half-started server. Admits each call through `ipc_call_budget.CallBudget`, then applies the gates of `ipc_request_policy.REQUEST_GATES` in order. Transport is AF_UNIX on POSIX and loopback TCP (`tcp_port`) where asyncio cannot open AF_UNIX streams, mirroring the DW track's fallback. The server holds no fixed request deadline: a call is bounded where it is made (session actor limit, then `call_backstop`), so a server configured above any fixed value is not cut. A request in flight ends with its client: the generated client keeps one request per connection and sends nothing while it waits, so `_process_until_client_leaves` races the request against a read on the connection and, when the connection closes (script stopped, or the call given up) or stray bytes arrive, cancels the call down to the MCP server instead of leaving it to hold the server until the tool's own limit. | ✅ |
| ipc_request_policy.py | Core | Stateless per-request gates of the MCP IPC server, each taking the request and the server's `CallerScope` and returning an error message or `None`: `read_only_policy_error` (a read-only run may call only tools declaring readOnlyHint), `script_file_policy_error` (a saved script, whose code the host never reviewed, may call only tools declaring readOnlyHint or builtins; inline Python is reviewed per call by the approval layer, so a mutating tool must be called from there), `path_policy_error` (workspace path policy on path-like parameters), `scope_gate_error` (employee/agent-scoped MCP discovery gate). `REQUEST_GATES` lists them in the order `MCPIPCServer._process_request` applies them, each with the name its refusal is logged under. A tool without safety metadata counts as mutating (fail-closed). | ✅ |
| tool_name_utils.py | Core | Single source of truth for MCP tool-name matching: `parse_mcp_tool_name` prefix parsing, `to_python_identifier` (dots/spaces/leading digits/Unicode → valid Python, Chinese names preserved, Python keywords prefixed), `build_tool_name_map` (deterministic `_2` collision suffixes, never shadowing a canonical name), `resolve_mcp_tool_name` (Python name → canonical), and `suggest_mcp_tool_names` (nearest callable names for an unknown tool, case/camel-case folded). Shared by L2 rendering, L3 doc paths, proxy invocation, and reload summaries. | ✅ |
| schema_doc_utils.py | Core | JSON Schema constraint extraction and markdown rendering for MCP tool documentation (params section, call examples, response notes), compact signature renderers (`render_signature` / `render_type` / `render_constraint`), and `render_output_type` / `build_returns_section` for concrete MCP `outputSchema` returns; untrusted output field names are restricted to safe identifiers or neutral placeholders. Signatures are keyword-only (`*,`), required-first, with short enum/regex hints. The L3 import/call example is emitted only when a required parameter carries a real `examples`/`default`; fabricated `"..."` placeholders are omitted. Dot-path (flattened) parameters render their call example as a `**{...}` dict splat so the sample stays valid Python. Rendering policy and budgets live in `doc_rendering`. | ✅ |
| proxy_service.py | Core | MCPSkillProxyService with warm-pool invoke, `skill_registry.get_mcp_skill_for_ipc` lookup, full `MCPConfig` + `_injected_auth_headers` restoration, required-arg validation that raises with the tool signature before the server is called (an unknown tool lists its closest callable names), explicit session cache (`cache_ttl_seconds` plus `cacheable_tools`; no implicit readOnlyHint fallback; successful writes clear the cache; mutating/dynamic tools are never cached), and `parse_mcp_result` (unwrap security envelope + JSON parse for PTC consumers). A call that fails comes back from the wrapper as `MCPToolFailure` and is raised as `RuntimeError`, not returned: a script would take the text for data and the read cache would keep it; the call itself runs under `call_backstop`. | ✅ |
| cache_policy.py | Core | Pure MCP result-cache policy: explicit `cache_ttl_seconds` plus `cacheable_tools` opt-in (no implicit readOnlyHint cache), short/prefixed/hyphen name aliasing, fixed-TTL `CacheBuckets`, and cache clear after writes. Dynamic ticket/status tools must never be allowlisted. | ✅ |
