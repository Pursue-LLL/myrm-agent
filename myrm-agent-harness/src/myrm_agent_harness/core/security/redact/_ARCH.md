# redact/

## Overview

Secret redaction domain — masks API keys, tokens and credentials before they reach the LLM context or log files (Layer 2 output redaction).
`masking.py` holds the value masking (a password or passphrase is hidden completely, a token keeps its head and tail), `patterns.py` the compiled regexes and shared replacers, `url_credentials.py` the URL credential regexes and replacers, `structured_fields.py` masks credential-named fields in JSON, JSON nested in a JSON string and Python repr diagnostics under one key policy, `engine.py` owns the bounded-replace pipeline and public APIs.
`file_view.py` picks the mode by file type. `__init__.py` is the aggregation facade exposing the public `core.security.redact` import surface.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Aggregation facade — re-exports engine + shared helpers (`_mask_token`). | ✅ |
| masking.py | Core | Leaf value masking — `_mask_token` hides a value under 18 characters completely and keeps the head 6 and tail 4 of a longer one (the head of a machine-issued token names its issuer, the rest is random); `_mask_secret(name, value)` hides the value of a password or passphrase (a name containing `pass` or `pw`) completely whatever its length, since the head and tail of a phrase a person chose disclose most of it. Every value replacer asks it by credential name; a name that merely contains `pass` (`bypass_token`) is hidden completely too, which errs on the side of showing less. | ✅ |
| patterns.py | Core | Compiled detection regexes (token prefixes, ENV/Auth/header/URL query/JWT, YAML/colon + form-urlencoded configs, CLI `=` flags, control chars), word-boundary key validation, form-body / ENV/YAML/CLI replacers. An unquoted value runs to whitespace or a quote, and a `&` ends it only before a `key=` pair or `amp;` (the shared `_UNQUOTED_VALUE`), so `PASSWORD=ab&cd` is masked whole while `token=abc&page=1` keeps `page=1`; a value cannot start with `&`, which keeps the YAML anchor in `password: &anchor`. The credential-name lists (ENV, YAML, keyword guard, CLI flags; the JSON list lives in `structured_fields.py`) each carry `passphrase`; a name that ends in `password`, `passwd` or `passphrase` is a credential even when its words run together (`PGPASSWORD`, `DBPASSWORD`), the unambiguous nouns the JSON policy already matches under any prefix, while the word-boundary rule stays for `token`, `key` and `auth` (`MYTOKEN=` is still not matched); `SSHPASS` and `MYSQL_PWD` have no password noun and are credentials by name (`_CREDENTIAL_VARIABLE_NAMES`, matched only as the last word of a key, so `SSHPASS_FILE` and `PWD=/home/user` are kept); and the lower-case `name_key=` detector bounds the name on both sides so a long underscore-and-keyword run costs time proportional to its length. A value that is entirely a variable reference (`$DB_PASS`, `${db_pass}`, `${X:?msg}`, `${X:-}`; a bare `$NAME` must be upper case, a non-empty `:-default` is a literal, and a literal after the closing `}` keeps the value masked) is kept by `_is_env_reference`, so compose/script variable names stay readable while `$Secret123` is still masked; the one known gap is a real password written as an upper-case `$WORD`. | ✅ |
| url_credentials.py | Core | URL credential regexes and replacers — `_DB_CONNSTR_RE` (database and broker DSN: `postgres(ql)`, `mysql`, `mongodb(+srv)`, `redis(s)`, `amqp(s)`, with an optional `+driver` and an optional user name, so `redis://:password@host` and `postgresql+asyncpg://` match), `_URL_USERINFO_RE` (`scheme://[user]:password@` for any scheme, user name optional, the scheme only starts at the beginning of a run of scheme characters so a long run is scanned once), `_URL_BARE_TOKEN_RE` (`scheme://TOKEN@host`, a private git remote). The password is replaced by `***` and the user name and the rest of the URL stay; a password that is a variable reference (`redis://:${REDIS_PASSWORD}@cache`, the usual compose form; `_is_env_reference`) is a name, not a secret, and stays readable like it does in `NAME=${NAME}`; the DSN regex runs before the generic one so a skill-export finding of a database URL keeps its `database_credential` kind. A password runs to the last `@` of its whitespace-free, quote-free run, so a raw `@` (`p@ss`) is masked whole and an e-mail address after the URL is not swallowed; the generic rule does not cross `/`, so an `@` in the path stays; the DSN password is capped at 1024 characters, which keeps the scan of a long run of `redis://:` bounded. | ✅ |
| structured_fields.py | Core | Credential-named field masking — plain JSON member (`_JSON_FIELD_RE`, shared with the skill content sanitizer), JSON member inside a JSON-encoded string (any escape depth), Python `repr` entries on pytest/exception diagnostic lines only. One key policy (`_is_secret_field_name`): bare credential words (including the variables known by name, `sshpass` and `mysql_pwd`) or an unambiguous credential noun suffix in snake/kebab/dotted/camel/Pascal spelling; bare `token`/`secret` are never suffix-matched, so `nextPageToken` / `token_count` stay readable. The noun list covers cloud-CLI credentials such as AWS `SecretAccessKey`, the backup and key-tool noun `passphrase`, and the channel credential nouns `app secret`, `signing secret`, `bot token`, `verification token` (vendor-neutral). Locale files key their form labels by those names (`"feishuAppSecret": "App Secret"`), so under a channel noun a value that is a plain label (`_PLAIN_LABEL_RE`: letters of any script joined by spaces, `-` or `_`, no digits, a lone word under 20 characters) is kept; every other name masks a label-shaped value like any other, and a passphrase made of words, a short letters-only value, or a random URL-safe base64 value without a digit under a channel noun is the known gap. A value that is a variable reference (`${API_KEY}`) is kept. An empty or blank plain-JSON value is left as written ("not set" is no secret and a reader needs it). | ✅ |
| file_view.py | Core | Per-file redaction by file type (`redact_file_text(path, text)`), shared by `file_read_tool` and `grep_tool`: a source file (by suffix) is redacted in source mode, so `total_api_tokens = 0` and `password: str` stay readable and only a string-literal credential is masked; every other file type (`.env`, YAML, JSON, TOML, shell, Markdown, unknown) is redacted in full. The path carries no `:range` suffix. | ✅ |
| engine.py | Core | Redaction engine — bounded replace (ReDoS guard), control-split token guard, `redact_sensitive_text` (`source_code=True` runs the name-based assignment passes only on lines that carry a string literal of eight characters or more; the value-shape passes run everywhere), `RedactingFormatter`, `escape_invisible_unicode`, `redact_for_llm`, `redact_for_display`. | ✅ |

## Key Dependencies

- None within `core.security` (foundation layer); the privacy tier's vendor-prefix table in `detection/leak_detector.py` is separate and maintained on its own
- Inside the package: `__init__.py` imports `engine.py`, `file_view.py` and `masking.py`; `file_view.py` imports `engine.py`; `engine.py` imports `masking.py`, `patterns.py`, `structured_fields.py` and `url_credentials.py`; `structured_fields.py` imports `masking.py` and `patterns.py`; `patterns.py` imports `masking.py` and `re`; `url_credentials.py` imports `patterns.py` (`_is_env_reference`) and `re`; `masking.py` imports only `re`

## Consumers

- `agent/security/redact.py` — thin facade re-exporting public + internal symbols
- `agent/skills/security/content_sanitizer.py` — imports `patterns.py` regexes, `url_credentials.py` regexes, the `_redact_value` key guard and `structured_fields._JSON_FIELD_RE` for structured content masking; its rule table names the capture group of each regex, so a change to a regex's group layout must be mirrored there (`tests/agent/skills/test_content_sanitizer.py` fails when a secret survives); the order of its rules decides the kind of a finding when two rules match the same secret (the longest match, then the earliest rule), which is why the DSN rule stands before the generic URL rule; it inherits the channel nouns of `_JSON_FIELD_RE` without the label exemption, which only shows a placeholder such as `"bot_token": "your-bot-token"` as a reviewable finding in the export preview
- `utils/errors.py`, `toolkits/browser/exceptions.py` — `redact_for_llm`
- `agent/middlewares/approval/_interrupt_payload.py` — `redact_for_display`
- `agent/meta_tools/file_ops/file_read_tool.py`, `agent/meta_tools/file_search/_redaction.py` — `redact_file_text`
- toolkits across browser / web_fetch / mcp / code_execution / memory — `redact_sensitive_text`
