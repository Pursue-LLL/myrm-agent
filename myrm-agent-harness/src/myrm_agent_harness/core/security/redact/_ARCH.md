# redact/

## Overview

Secret redaction domain — masks API keys, tokens and credentials before they reach the LLM context or log files (Layer 2 output redaction).
`masking.py` holds the value masking (a password or passphrase is hidden completely, a token keeps its head and tail), `patterns.py` the compiled regexes and shared replacers, `header_patterns.py` the API-key and Cookie header rules, `command_patterns.py` the command-line credential rules (`curl -u/-U/-b`, `sshpass -p`, `mysql -p`, `docker login -p`, `redis-cli -a`, `openssl -pass`), `command_line.py` the entry of the commands the audit log and the background-job registry keep (`redact_command_line`) and the preview of the commands a log line quotes (`command_preview`), `url_credentials.py` the URL credential regexes and replacers, `structured_fields.py` masks credential-named fields in JSON, JSON nested in a JSON string and Python repr diagnostics under one key policy, `engine.py` owns the redaction pipeline and public APIs, and every pass applies its regex through the bounded replace of `bounded_replace.py`.
`file_view.py` picks the mode by file type. `__init__.py` is the aggregation facade exposing the public `core.security.redact` import surface.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Aggregation facade — re-exports engine, `redact_command_line`, `command_preview` + shared helpers (`_mask_token`). | ✅ |
| masking.py | Core | Leaf value masking — `_mask_token` hides a value under 18 characters completely and keeps the head 6 and tail 4 of a longer one (the head of a machine-issued token names its issuer, the rest is random); `_mask_secret(name, value)` hides the value of a password or passphrase (a name containing `pass` or `pw`) completely whatever its length, since the head and tail of a phrase a person chose disclose most of it. Every value replacer asks it by credential name; a name that merely contains `pass` (`bypass_token`) is hidden completely too, which errs on the side of showing less. | ✅ |
| bounded_replace.py | Core | `_replace_pattern_bounded` — `pattern.sub` that cuts a text longer than 32 KB into 16 KB chunks overlapping by 4 KB, so a regex that backtracks on adversarial text takes time proportional to the text; a match seen in two chunks is applied once, and the longer one wins, because the earlier chunk may see it cut at its own end. | ✅ |
| patterns.py | Core | Compiled detection regexes (token prefixes, ENV/Authorization/URL query/JWT, YAML/colon + form-urlencoded configs, CLI flags, control chars), word-boundary key validation, form-body / ENV/YAML/CLI replacers. An unquoted value runs to whitespace or a quote, and a `&` ends it only before a `key=` pair or `amp;` (the shared `_UNQUOTED_VALUE`), so `PASSWORD=ab&cd` is masked whole while `token=abc&page=1` keeps `page=1`; a value cannot start with `&`, which keeps the YAML anchor in `password: &anchor`. The credential-name lists (ENV, YAML, keyword guard; the JSON list lives in `structured_fields.py`) each carry `passphrase`; a CLI flag (`_CLI_FLAG_RE`, space or `=` before the value) takes an unquoted value that runs to whitespace or a quote, a backslash keeping the next character in it, so `hunter2;rest`, `hunter2&rest` and `pa\ ss` are masked whole (an argument list printed without its quoting cannot tell a separator in the value from one between two commands, and a value cut there would leave the rest of the credential readable); the flag is a credential when its name ends in `password`, `passwd`, `passphrase`, `secret`, `api-key`, `access-key` or `secret-key` behind any words (`--db-password`, `--aws-secret-access-key`), or in `token` behind a word that makes it one (`--auth-token`, `--bot-token`, a bare `--token`), while `--password-file`, `--secret-name`, `--no-password`, `--skip-…` and the program's own `--failure-token` or `--max-token` are not (a flag that takes no value yet ends in such a noun, `--ask-password site.yml`, masks the word after it); a name that ends in `password`, `passwd` or `passphrase` is a credential even when its words run together (`PGPASSWORD`, `DBPASSWORD`), the unambiguous nouns the JSON policy already matches under any prefix, while the word-boundary rule stays for `token`, `key` and `auth` (`MYTOKEN=` is still not matched); `SSHPASS` and `MYSQL_PWD` have no password noun and are credentials by name (`_CREDENTIAL_VARIABLE_NAMES`, matched only as the last word of a key, so `SSHPASS_FILE` and `PWD=/home/user` are kept); and the lower-case `name_key=` detector bounds the name on both sides so a long underscore-and-keyword run costs time proportional to its length. A value that is entirely a variable reference (`$DB_PASS`, `${db_pass}`, `${X:?msg}`, `${X:-}`; a bare `$NAME` must be upper case, a non-empty `:-default` is a literal, and a literal after the closing `}` keeps the value masked) is kept by `_is_env_reference`, so compose/script variable names stay readable while `$Secret123` is still masked; the one known gap is a real password written as an upper-case `$WORD`. | ✅ |
| header_patterns.py | Core | Header rules — `_SECRET_HEADER_RE` (an API-key style header or property such as `x-api-key:`, value masked by `_mask_token`), A `Cookie:` or `Set-Cookie:` header line hides its whole value, a `; `-separated list that carries the session (`_COOKIE_HEADER_LINE_RE` for a raw line, a curl `> ` / `< ` trace line or the escaped line break of a dumped request; `_COOKIE_HEADER_QUOTED_RE` for a quoted `-H` argument): the value ends at the end of the line, at an escaped line break or at the quote that closes a JSON string, and a quoted argument ends at the quote that opened it, so the record or command around it stays intact; the name must not be glued to a word, `-` or a quote (`X-Cookie:` and `Cookie policy:` are not headers). `_redact_secret_headers` is the pass `engine.py` runs; `agent/skills/security/content_sanitizer.py` reads `_SECRET_HEADER_RE`. | ✅ |
| command_patterns.py | Core | Command-line credential rules, one table row per tool — `curl -u/--user` and `-U/--proxy-user user:password` (the user name stays; the short option may close a cluster of short flags such as `-sSu`), `curl -b/--cookie name=value; …` (masked whole; a value without `=` is a cookie jar file and stays); one curl command carries a login, a proxy login and a cookie together, and every one of them is masked (the text after the first one is scanned as it stands, so a quoted argument that spells ` -u user:password` is masked too). `sshpass -p password` (`sshpass` reads only its own options: `-f`, `-d` and `-P` take an argument, `-e` and the others do not, and the first word that is no option ends them, so the `-p` of the wrapped `ssh -p 2222` is a port and stays), the attached `-ppassword` of `mysql`, `mysqldump` and `mysqladmin` (a bare `-p` prompts and stays), `docker login -p/--password`, `redis-cli -a/--pass` (its `-p` is a port) and the passphrase after `pass:` in `openssl -pass/-passin/-passout/-password` (`env:`, `file:` and `stdin` name a reference and stay). Each rule is anchored on the command name, a whole word that may carry a path, and stays inside one simple command: a `|`, `;`, `&` or line break outside a quoted argument, or the escaped line break of a JSON string, ends it (a backslash before the line break, raw or inside a JSON string, continues the command), at most 256 characters or quoted arguments lie between the name and the option, and the next occurrence of the name ends that search (it starts its own), so a text that repeats the name costs a few steps per occurrence. The line break itself may precede the option, so `-u user:password` at the start of the line after a `curl` line is masked too. The argument may be single-quoted, double-quoted or double-quoted inside a JSON string. A value that is a variable reference (`$PASSWORD`, `${X}`), a command substitution, already masked or without a letter or digit (`sshpass -p,` in a sentence) is kept. Other spellings of a password option are not recognised (`--pass`, `--db-pass`, `ldapsearch -w`, `curl --pass`, `--proxy-pass`, `--oauth2-bearer`, `openssl passwd -1 PASSWORD` and `openssl enc -k PASSWORD`). Passwords that are fed on stdin (`echo PASSWORD | sudo -S`, `docker login --password-stdin`, `gh auth login --with-token`, `gpg --passphrase-fd`) or given as a positional argument (`aws configure set`, `npm config set`, `git config`) have no option name or command anchor to go by and are the known gap. `engine.py` runs `_redact_command_credentials` as the first step of `redact_sensitive_text`, on every line, also in source mode, because a command name is no variable name; it runs before the generic passes because their value may touch a separator and swallow the command name that anchors a rule (`tool --token x;curl -u a:pw`); a text that never names the command skips its rule. | ✅ |
| command_line.py | Core | `redact_command_line(command)` — the entry of the commands the audit log and the background-job registry keep: the credential-named parameters first, then the shared redactor (its first step is the command rules). A parameter is a long option named by one of 18 credential words (`token`, `password`, `pwd`, `secret`, `key`, `auth`, `bearer`, ...) — `--token x`, `--token=x`, `--token="x"` — or an assignment whose name ends in one (`TOKEN=x`, `MY_KEY=x`), and its value is one quoted string or one run of unquoted characters (`_VALUE`: a single-quoted string ends at the next `'`, a double-quoted one at the next `"` that no backslash escapes, and either holds anything: a space, a line break, `; | & < > ( )`, a backtick, the other kind of quote; a run of unquoted characters ends at whitespace, a quote, `; | & < > ( )` or a backtick, and a backslash keeps the next character in it) replaced by `***REDACTED***` (the shared redactor that follows may shorten it to `***`); a quote that follows a value is never read as its next part, so the arguments after a credential typed inside a quoted argument (`-e "API_KEY=x" -e "B=1"`) stay as written; a quoted string that is empty or never closes has nothing or no end to mask and is not matched; a word after a short option is the value of that option and stays, and whitespace and line breaks stay as written. The name match errs on the side of showing less (`sort --key=2` and `gh --auth login` are masked), which is why this pass is not part of `redact_sensitive_text`: tool output, file content and the skill-export preview keep such text readable. The assignment pass of the shared redactor then reads the masked value of an environment-named parameter (`token`, `password`, `auth`, ...) up to the next whitespace, so a command word glued to it after `;` or `|` is folded into the mask (`tool --token=***RED...curl`) or lost (`tool --password=*** -u ...`) while no secret is left; a parameter such as `--key` keeps it. The CLI-flag rule of the shared redactor masks to the whitespace as well, so a word glued to the value of a flag it knows (`--client-secret x;curl`) is part of the mask. `command_preview(command, limit)` is the form for a log line: it masks the whole command and cuts the masked text to `limit` characters (`...` after a cut), because a value cut off before its closing quote is an unterminated quote that the named pass does not match, so a cut made first would leave the start of the value. | ✅ |
| url_credentials.py | Core | URL credential regexes and replacers — `_DB_CONNSTR_RE` (database and broker DSN: `postgres(ql)`, `mysql`, `mongodb(+srv)`, `redis(s)`, `amqp(s)`, with an optional `+driver` and an optional user name, so `redis://:password@host` and `postgresql+asyncpg://` match), `_URL_USERINFO_RE` (`scheme://[user]:password@` for any scheme, user name optional, the scheme only starts at the beginning of a run of scheme characters so a long run is scanned once), `_URL_BARE_TOKEN_RE` (`scheme://TOKEN@host`, a private git remote). The password is replaced by `***` and the user name and the rest of the URL stay; a password that is a variable reference (`redis://:${REDIS_PASSWORD}@cache`, the usual compose form; `_is_env_reference`) is a name, not a secret, and stays readable like it does in `NAME=${NAME}`; the DSN regex runs before the generic one so a skill-export finding of a database URL keeps its `database_credential` kind. A password runs to the last `@` of its whitespace-free, quote-free run, so a raw `@` (`p@ss`) is masked whole and an e-mail address after the URL is not swallowed; the generic rule does not cross `/`, so an `@` in the path stays; the DSN password is capped at 1024 characters, which keeps the scan of a long run of `redis://:` bounded. | ✅ |
| structured_fields.py | Core | Credential-named field masking — plain JSON member (`_JSON_FIELD_RE`, shared with the skill content sanitizer), JSON member inside a JSON-encoded string (any escape depth; a match starts where the run of backslashes starts, so a long run costs time proportional to its length), Python `repr` entries on pytest/exception diagnostic lines only. One key policy (`_is_secret_field_name`): bare credential words (including the variables known by name, `sshpass` and `mysql_pwd`) or an unambiguous credential noun suffix in snake/kebab/dotted/camel/Pascal spelling; bare `token`/`secret` are never suffix-matched, so `nextPageToken` / `token_count` stay readable. The noun list covers cloud-CLI credentials such as AWS `SecretAccessKey`, the backup and key-tool noun `passphrase`, and the channel credential nouns `app secret`, `signing secret`, `bot token`, `verification token` (vendor-neutral). Locale files key their form labels by those names (`"feishuAppSecret": "App Secret"`), so under a channel noun a value that is a plain label (`_PLAIN_LABEL_RE`: letters of any script joined by spaces, `-` or `_`, no digits, a lone word under 20 characters) is kept; every other name masks a label-shaped value like any other, and a passphrase made of words, a short letters-only value, or a random URL-safe base64 value without a digit under a channel noun is the known gap. A value that is a variable reference (`${API_KEY}`) is kept. An empty or blank plain-JSON value is left as written ("not set" is no secret and a reader needs it). | ✅ |
| file_view.py | Core | Per-file redaction by file type (`redact_file_text(path, text)`), shared by `file_read_tool` and `grep_tool`: a source file (by suffix) is redacted in source mode, so `total_api_tokens = 0` and `password: str` stay readable and only a string-literal credential is masked; every other file type (`.env`, YAML, JSON, TOML, shell, Markdown, unknown) is redacted in full. The path carries no `:range` suffix. | ✅ |
| engine.py | Core | Redaction engine — `redact_sensitive_text` (the command-line credential rules first, then the control-split token guard and the value, name and header passes; `source_code=True` runs the name-based passes, the assignments and the API-key and cookie headers, only on lines that carry a string literal of eight characters or more; the value-shape passes and the command-line credential rules run everywhere), `RedactingFormatter`, `escape_invisible_unicode`, `redact_for_llm`, `redact_for_display`. | ✅ |
