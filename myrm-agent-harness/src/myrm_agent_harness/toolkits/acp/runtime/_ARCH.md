# runtime/

## Overview
ACP Runtime backends — unified interface for ACP and CLI agents.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | ACP Runtime backends — unified interface for ACP and CLI agents. | ✅ |
| _base.py | Internal | Base class for RuntimeBackend implementations — timeout control, truncation, error handling; `build_safe_env` gives a child process only the core variables (shared `CORE` policy of `core/security/process_env/env_isolation.py`) plus its CLI's login-home variable, then the configured `env` by `auth_mode`, then `NODE_USE_SYSTEM_CA=1` while enterprise network compatibility is on (`infra/tls_compat.py::with_node_system_ca`; a value from `env` wins) — `CliRuntime` and `AcpRuntime` both spawn with it; the turn generator is closed with `aclosing`, so a timeout, a failure or an abandoned stream stops the backend process; `KEEPALIVE_SECONDS` and `working_status` are the silence heartbeat both runtimes share. | ✅ |
| acp/ | Core | ACP runtime sub-package: `AcpRuntime` (one persistent ACP agent process per backend), its callback handler (events, permissions, file access with path safety) and the bounded stop of an agent that stopped reading. See [acp/_ARCH.md](acp/_ARCH.md). | ✅ |
| cli/ | Core | CLI runtime sub-package: `CliRuntime` (one CLI agent process per turn), per-CLI dialects, process ownership, NDJSON turn parsing, failure classification, `CliSessionBook` (CLI session continuity). See [cli/_ARCH.md](cli/_ARCH.md). | ✅ |
| image_blocks.py | Core | `load_image_blocks`: the image files of a turn as `ImageBlock`s (media type + base64) in order, for both runtimes (a CLI stdin message block, an ACP image content block); the format comes from the file's first bytes via the shared `utils/mime_types.detect_image_mime`, kept to `VISION_IMAGE_MIME_TYPES` (PNG, JPEG, GIF, WebP), never its name; an unreadable or non-image file is skipped with an `image_skipped` WARNING that does not name the path. Blocking I/O: both runtimes call it in a thread. | ✅ |
| pool.py | Core | Runtime pool: multi-backend management, concurrency control (global semaphore + per-backend serialization), config MCP passthrough gated by backend `supports_mcp` capability, and per-turn `images` (local image files) gated by `supports_images` the same way (a backend without it gets `None` and the turn opens with an `images_not_sent` status update). A `oneshot` turn runs on a private backend (fresh session, closed afterwards, registered for `cancel` / `close_all`), so it never touches the shared backend's persistent session or process. `release_resident()` stops only the resident (ACP) backends and keeps CLI backends with their `--resume` ids, so a host can reclaim idle processes without ending CLI sessions. An optional `cli_session_store` is handed only to the shared persistent backends (never to oneshot private backends), so CLI sessions also survive a restart of the host process. No periodic liveness supervision: a resident ACP process that exited is reconnected by its next `run_turn`, and a CLI backend has no process between turns by design. | ✅ |
