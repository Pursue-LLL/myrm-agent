# browser/domain_filter/

## Overview

Deep domain filtering — four-layer defense-in-depth for browser network egress (CSP + protocol interception + main-thread hardening + CDP audit), plus ad/tracker domain blocking.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| `__init__.py` | Package | Public facade: `DomainAllowlist`, `install_domain_filter` (four-layer installer with resource blocking; registers the Layer 0 and Layer 2 scripts as init scripts of the context, in that order, for a non-empty allowlist only; forwards `allow_private_networks` to the Layer 1 filter) and the re-exported `build_csp_meta_script` / `build_init_script`. `DomainAllowlist` reads its entries through `core.security.domain_match`, the reading the permission engine uses (`example.com` exactly, `*.example.com` and `.example.com` with every subdomain); callers use `is_allowed` (allowlist semantics) or `is_blocked` (blocklist semantics) on the same matching core. | ✅ |
| `scripts.py` | Core | The page-side scripts `install_domain_filter` registers with `add_init_script`. `build_csp_meta_script` makes the allowlist's Content-Security-Policy `<meta>` (`connect-src`, `script-src`, `frame-src`, `object-src 'none'`; img/style/font/media stay open; an empty allowlist installs no filter, so it is refused with `ValueError`) and inserts it as the first child of the document's head: it waits for the parser to create the head (a `MutationObserver` that disconnects once the policy is in or the document is parsed), so the policy precedes the page's own scripts, and a document that never gets a head (SVG) gets none. The policy governs the document's own connections and refuses `blob:` and `data:` Workers; a Worker started from a URL answers to its own response's policy, so Layer 1 stops its HTTP requests and a WebSocket it opens itself is judged by no layer. The policy is document-scoped, and the first document of a same-origin `window.open` popup reuses the opener's initial window, which the init script saw only as `about:blank`: the same script therefore wraps the `WebSocket`, `Worker` and `SharedWorker` constructors in a `Proxy` that puts the policy on the current document, once per document, before the real constructor runs (measured; see `BROWSER_SYSTEM.md` §10). `build_init_script` hardens `RTCPeerConnection`, `webkitRTCPeerConnection`, `WebTransport` and `navigator.serviceWorker.register` with non-writable, non-configurable properties; Web Workers are left alone. Window-global, so it also applies in those popups. | ✅ |
| `ad_domains.py` | Data | Lazily-loaded frozenset of ~3500 ad/tracker domains (bundled `assets/ad_domains.txt`) | ✅ |
| `context_lists.py` | Core | `DomainListPolicy` (blocklist first, then allowlist; empty lists impose nothing; a missing hostname fails closed under an allowlist) plus the per-context registry `bind_domain_lists` / `domain_lists_for` (weak-keyed by `BrowserContext`, like `utils.private_origins`). One rule, two consumers: the Layer 1 request filter and the navigation guard's redirect-hop check, so a hostname gets the same verdict whichever way it was reached. | ✅ |
| `http_filter.py` | Core | Layer 1 route filter: hop-by-hop private network / cloud-metadata revalidation (empty hostname fails closed). Cloud mode checks every request type; local mode (`allow_private_networks`) checks only documents, against the session's explicit-origin grants (cloud metadata is never relaxed; a hostname resolving to loopback, link-local or metadata counts as that address), because subresources of a local page are left to Chromium's private-network-access rules. Every later rule still applies, ad/tracker blocklist, domain block/allow lists, resource-type blocking; document hops that violate policy are aborted and the tab reset to `about:blank`. Only requests routed to the filter are judged: patchright does not route the hops of a document redirect, so the filter sees the entry URL and subresources but not a redirect target. It binds its `DomainListPolicy` to the context, and `navigation/ssrf_guard.py` replays the redirect chain after the load, judging private and metadata targets by address and every hop after the entry URL against the same domain lists. | ✅ |
