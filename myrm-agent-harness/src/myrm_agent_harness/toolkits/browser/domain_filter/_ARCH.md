# browser/domain_filter/

## Overview

Deep domain filtering — four-layer defense-in-depth for browser network egress (CSP + protocol interception + main-thread hardening + CDP audit), plus ad/tracker domain blocking.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| `__init__.py` | Package | Public facade: `DomainAllowlist`, `install_domain_filter` (four-layer installer with resource blocking; registers the Layer 0 and Layer 2 scripts as init scripts of the context, in that order, for a non-empty allowlist only; forwards `allow_private_networks` to the Layer 1 filter) and the re-exported `build_csp_meta_script` / `build_init_script`. `DomainAllowlist` reads its entries through `core.security.domain_match`, the reading the permission engine uses (`example.com` exactly, `*.example.com` and `.example.com` with every subdomain); callers use `is_allowed` (allowlist semantics) or `is_blocked` (blocklist semantics) on the same matching core. | ✅ |
| `scripts.py` | Core | The page-side scripts `install_domain_filter` registers with `add_init_script`. `build_csp_meta_script` makes the allowlist's Content-Security-Policy `<meta>` (`connect-src`, `script-src`, `frame-src`, `object-src 'none'`; img/style/font/media stay open; an empty allowlist installs no filter, so it is refused with `ValueError`) and inserts it as the first child of the document's head: it waits for the parser to create the head (a `MutationObserver` that disconnects once the policy is in or the document is parsed), so the policy precedes the page's own scripts. A document with a root element but no head (XML, SVG) is given one in the XHTML namespace when the policy is first needed, since a policy `<meta>` is enforced only inside the head (the head is removed again when the engine does not read it as the document's head). The policy governs the document's own connections and refuses `blob:` and `data:` Workers; a Worker started from a URL answers to its own response's policy, so Layer 1 stops its HTTP requests and a WebSocket it opens itself is judged by no layer. The policy is document-scoped, and the first document of a same-origin `window.open` popup reuses the popup's initial window, which the init script normally saw only as `about:blank`: the same script therefore wraps the `WebSocket`, `Worker` and `SharedWorker` constructors in a `Proxy` that puts the policy on the current document, once per document, before the real constructor runs (measured; see `BROWSER_SYSTEM.md` §10). A popup that keeps its opener can run its first script before the init scripts are registered, and a channel that script opens first is covered by neither Layer 0 nor Layer 2 (same section). `build_init_script` hardens `RTCPeerConnection`, `webkitRTCPeerConnection`, `WebTransport` and `navigator.serviceWorker.register` with non-writable, non-configurable properties; Web Workers are left alone. Window-global, so it also applies in those popups. Both scripts also run in the world of the agent's own JavaScript (`agent_world.py`): the policy script is idempotent per document whichever world ran first (it adds the `<meta>` only when none of the head's CSP metas already holds the policy) and evaluates to a function that returns whether the current document carries the policy; the hardening leaves a property that is already locked down as it is, because on an engine whose agent world is the page's own world the same window is hardened twice and defining a locked property again throws. | ✅ |
| `agent_world.py` | Core | The policy in the world the agent's own JavaScript runs in. `BrowserSession.evaluate` is the one entry of agent-written script into a page, and `page.evaluate` runs it, under patchright (the default engine), in the driver's isolated world: its own constructors over the page's DOM, where the main-world init scripts' `WebSocket` / `Worker` wrappers and hardening are absent, and a document that carries no policy `<meta>` (a same-origin popup's reused window) lets the expression open a WebSocket or a Worker to any host. An engine whose driver evaluates in the page's own world (stock Playwright, which Camoufox runs on) has run both scripts there already, and the arm finds the window hardened and leaves it as it is. `agent_world_expression` returns the text `page.evaluate` is handed: for a context whose filter holds an allowlist, an arm (the policy script, the hardening script once per window, then a check that the document carries the policy) followed by the agent's text as the JSON literal of an inner `eval`, so the text keeps its own semantics (a leading `'use strict'`, error positions). The text is trimmed and, when it reads as a function expression, parenthesized in the page's own JavaScript engine, the way the driver does it, so the two cannot disagree on what whitespace is; for any other context, the text as written. The arm's global is defined non-writable and non-configurable, so the agent's script cannot take the check down for the calls that follow. A document with a root element but no head (XML, SVG) is given a head to hold the policy; a document that still cannot carry it (no root element) refuses the expression with a thrown `Error`. The arm covers the window the expression runs in: a frame or popup window reached through a DOM handle is another realm (an `RTCPeerConnection` there is not hardened; a WebSocket or Worker there is refused only by the policy its document carries), measured in `BROWSER_SYSTEM.md` §10. | ✅ |
| `ad_domains.py` | Data | Lazily-loaded frozenset of ~3500 ad/tracker domains (bundled `assets/ad_domains.txt`) | ✅ |
| `context_lists.py` | Core | `DomainListPolicy` (blocklist first, then allowlist; empty lists impose nothing; a missing hostname fails closed under an allowlist) plus the per-context registry `bind_domain_lists` / `domain_lists_for` (weak-keyed by `BrowserContext`, like `utils.private_origins`). One rule, two consumers: the Layer 1 request filter and the navigation guard's redirect-hop check, so a hostname gets the same verdict whichever way it was reached. `agent_world.py` reads a context's allowlist from the same registry. | ✅ |
| `http_filter.py` | Core | Layer 1 route filter: hop-by-hop private network / cloud-metadata revalidation (empty hostname fails closed). Cloud mode checks every request type; local mode (`allow_private_networks`) checks only documents, against the session's explicit-origin grants (cloud metadata is never relaxed; a hostname resolving to loopback, link-local or metadata counts as that address), because subresources of a local page are left to Chromium's private-network-access rules. Every later rule still applies, ad/tracker blocklist, domain block/allow lists, resource-type blocking; document hops that violate policy are aborted and the tab reset to `about:blank`. Only requests routed to the filter are judged: patchright does not route the hops of a document redirect, so the filter sees the entry URL and subresources but not a redirect target. It binds its `DomainListPolicy` to the context, and `navigation/ssrf_guard.py` replays the redirect chain after the load, judging private and metadata targets by address and every hop after the entry URL against the same domain lists. | ✅ |
