# browser/session/download/

## Overview
File downloads of a browser session. `BrowserSession` takes a `DownloadConfig` to turn download support on: with one it runs a `DownloadManager`, without one it has none and its browser contexts accept no download at all (a pooled context starts with `accept_downloads=False`; a session with a config opts its own context in). Every download is judged at the address it came from before any byte is kept, whoever started it: the agent's `download_url` request (one request at a time per page, taking the first download its page starts) or the page itself. A page-started download is first admitted by the config's `admit_page_started` policy, which the embedding application derives from its permission policy (nobody can be asked about a download a page starts, so only a positive answer admits it). A download that is not admitted, not judged or not kept is cancelled and deleted; once a download is processed the browser keeps nothing of it, so the saved copy is the only one left. A saved file is the browser's own finished copy, written under a unique, sanitized name into the downloads directory. That directory lies below a root the caller trusts (the workspace, which the sandboxed agent can also write), is reached without following a link, and is bounded by a file-count and a total-size quota counted from the directory itself. The session-level APIs over the manager live one level up in `browser_session_download_mixin.py`; the tool layer (`tools/download_actions.py`) turns the records and errors into what the agent reads.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| `__init__.py` | Package | Public facade: `DownloadConfig`, `PageStartedPolicy`, `DownloadManager`, `DownloadError`, `DownloadResult`, `DownloadRefusal`, `DownloadMark`, `DownloadActivity`. | ✅ |
| `config.py` | Core | `DownloadConfig` (the downloads directory and the trusted root `confined_to` it must lie below, both required; per-file size limit, save timeout, concurrency, allowed extensions with the default whitelist, the quota `max_files` / `max_total_mb`, the `admit_page_started` policy) and `PageStartedPolicy`: `Callable[[str], bool]` called with the address a page-started download came from (the page's own address for a `blob:` or `data:` download, which names none) and answering whether the page may save it on its own; a config without a policy admits every download that passes the address check. Kept apart from the manager that applies it. | ✅ |
| `errors.py` | Core | `DownloadError(reason, detail)`: a download that is not kept. `reason` is written for the agent and names no address; `detail` (the browser's own words) is for the log only. | ✅ |
| `records.py` | Data | The shapes the manager, the storage and the session-level APIs exchange: `DownloadResult` (one saved file), `DownloadRefusal` (file name and reason of a page-started download that was not kept), `DownloadMark` / `DownloadActivity` (a moment in a session's downloads, and what was saved or refused after it). | ✅ |
| `storage.py` | Core | `DownloadStorage` and `sanitize_filename`: the disk side. A save checks the file type, then opens the downloads directory below the trusted root without following a link (`core.security.path.open_directory_beneath`; a link on the way is refused with the reason told to the agent; the directory is created, with a `.gitignore` that ignores it, by the first save) and refuses at once when the quota is already used up. It then waits, within the save timeout, for the browser to finish the download and report its own copy (`Download.path()`, which needs a browser this process launched or attached to over CDP), refuses an empty file, a file over the file limit and one that would take the directory over its quota, claims its name with an exclusive create (so downloads saving at the same moment never choose the same name; a taken name gets ` (n)` before the extension; a link planted under the name makes the create fail and is never followed) and copies the content in chunks through the descriptor that create returned. A failure, refusal or cancellation removes the claim. A name is cut to 200 UTF-8 bytes at a character boundary, keeping a short extension. The quota is read from the directory itself (`scandir` on its descriptor), because sessions of one workspace share it; it is a soft cap that concurrent saves can overshoot by what they save together, and nothing is evicted. | ✅ |
| `manager.py` | Core | `DownloadManager`: listens for, admits, judges, processes and records downloads. It holds no URL policy: the session hands it the verifier for the address a download came from, and the config hands it the policy for downloads a page starts. `download_url` hands the address to the page as an argument (never spliced into script), takes the first download the page starts, and stops the navigation it started when it gives up; every other download of the page goes through the page path, and so does one the request claimed but never took. A page-started download is admitted and judged at once, without waiting for a free slot, and one that is not kept is remembered (the latest five, with the reason) so the agent can be told. `mark` / `activity_since` report what was saved or refused after a moment, once the downloads in flight have settled (bounded by the save timeout). Discarding a download is bounded for the caller and carries on in the background. Log lines show a download's URL as scheme, host and path with what looks like a credential masked, and the text they quote is bounded. | ✅ |
