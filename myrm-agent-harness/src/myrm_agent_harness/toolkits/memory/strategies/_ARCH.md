# strategies/

## Overview
Optional memory strategies: forgetting, extraction, deduplication, consolidation, preference stability, pattern discovery, staleness review.

| consolidation.py | Core | Cross-session memory consolidation orchestrator. Analyzes the oldest memories not yet covered via LLM to detect contradictions, redundancies, and generate insights, one namespace group at a time (`consolidation_groups.py`): every group is analyzed before anything is written, so a model failure on any group writes nothing and holds the stamp. The stored timestamp is a covered-through mark over the order memories reached the store, kept in a bookkeeping row: it advances only as far as the analyzed window reached and never past a write that is still being persisted (the run's horizon is `store_stamp.settled_through()`), so a backlog larger than one run is drained over consecutive runs, and it holds when a source was unreadable or the batch aborted or failed outright. A stored value that cannot be parsed, is naive or is in the future is ignored with a warning (a foreign value must not raise in or stall the time gates; the stamp clock leads the wall clock after a step back, so a stamp written then can be in the future until the wall clock catches up). Once the model has answered, applying it (writes, undo journal, stamp, completion callback) is not interrupted by a cancel of the caller: `_run_to_completion` delivers the cancel when the writes are done, so a cycle is never left half applied and the caller's maintenance lock is held until then. A cycle that changed existing memories saves its undo journal (`consolidation_undo.py`); a cycle that only adds insights leaves the undo slot to the earlier cycle that did. Insights derive from the chats of every memory of the namespace group they were drawn from and, when the cycle changed existing memories, are journaled with its other writes, so undoing the cycle removes them. The completion callback runs once the model has answered and the answer was applied or needed no writes; the soft lock, a window with no group worth a model call and a model failure end the run without it. | ✅ |
