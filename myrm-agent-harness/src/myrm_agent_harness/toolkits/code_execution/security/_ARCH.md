# security/

## Overview
Execution security — shell command analysis, blacklists, validators, and C-level PEP 578 sandboxing.

| protected_instruction_command.py | Core | The shell-side reading of the protected instruction files: `protected_instruction_mutation_target(command)` names the protected file a command line writes (redirect, `sed -i`, `tee`, `cp`, `mv`, `rm`, `truncate`, the PowerShell cmdlets and cmd commands that do the same such as `Set-Content`, `Remove-Item`, `copy`, `del`, an interpreter opening it for writing), or `None`. | shell_command_analyzer.py | Core | Shell Command Analyzer — multi-layer security (L1: binary/Unicode, language-independent and exposed alone as `analyze_hidden_characters` for Python source that no shell reads, L1.5: ANSI-C/locale quoting evasion BLOCK, shell text only, L2: injection/dangerous commands, L2.5: SQL statement guard, L3: suspicious patterns, L3c: protected instruction file mutation via `protected_instruction_mutation_target` (reports the matched name as the threat's evidence), readings: L2–L3c judge every reading of the command (`shell_command_readings.command_readings`: the line as written, each script and substitution it hands to a shell, each command apart), not only the line as written; a line that hands a shell more scripts than the readings can hold is refused (BLOCK, category `obfuscation`); `is_destructive_command` (snapshot trigger) and `is_integration_mutation_command` read the same texts). | shell_command_readings.py | Core | The texts the shell command rule tables are matched against, bounded. `command_readings(command)` returns the line as written, then every command line it hands to a shell — each `sh -c` / `eval` script and `trap` handler wherever the interpreter stands in a command (behind `sudo`, `then`, `docker exec ctr`, a redirection, a `case` arm; found by trying each word of `read_commands`) and the body of each `$(...)` / backtick substitution (`core.security.shell_wrapper_peel.substitution_bodies`) — then each command of the line and of those scripts apart (`split_command_spans`, so `rm -rf ~&&echo` and `a; rm -rf ~` end at their command; also without the closer of a grouping glued to its end, so the `uv.lock)` of `(cd d && echo x > uv.lock)` is read). Each reading is expanded once and the readings beside the line add up to at most `MAX_COMMAND_READINGS` texts and `MAX_READING_CHARS` characters. The scripts are read first, since what a line hides inside quotes stands in no other reading: when they do not fit, `CommandReadings.complete` is False and the analyzer refuses the line; the commands apart only restate that text, so they fill what is left of the bounds (those of a script before those of the line) and a long script or heredoc is judged on what fits instead of being refused for its length. A command behind a prefix such as `sudo` / `env` / `timeout` is judged where it stands, with its quotes, so the quoted text of its arguments stays masked. | ✅ |
