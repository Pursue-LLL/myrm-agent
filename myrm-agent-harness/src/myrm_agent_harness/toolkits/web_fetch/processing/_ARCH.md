# processing/

## Overview
Post-fetch content processing: HTML to Markdown, pruning, sanitization, URL normalization and rewriting, full-content delivery (one shared budget, complete text saved), anti-bot, binary routing.

## File Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Re-exports ContentPipeline on first access, so importing `spill` does not load the HTML pipeline | ✅ |
| pipeline.py | Core | ContentPipeline — HTML/JSON/XML to Markdown; a text response (`PayloadKind.TEXT`) becomes a Document verbatim. A Document built from a source the fetcher cut at its size ceiling (`FetchResult.source_truncated`) carries `SOURCE_TRUNCATED_KEY` in its metadata, whichever path `process` took (the binary router flags the files it cuts itself); the pipeline itself never shortens a Document, so what the page holds reaches the caller | ✅ |
| content_sanitize.py | Util | Strip base64 blobs from markdown | ✅ |
| content_pruning.py | Util | Boilerplate/noise pruning; a page nested beyond the scoring limit skips the scoring passes and keeps the structural cleanup. An element is dropped as hidden when its class is `hidden`, starts with `hidden-` or is hidden by breakpoint (`sm`, `md`, `lg`, `xl`, `2xl` followed by `:hidden`, a copy shown on small screens only); a state variant such as `dark:hidden` or `group-hover:hidden` hides content only for a theme or pointer state, so the element stays (a dual-theme code block keeps one copy) | ✅ |
| html_to_markdown.py | Util | HTML to Markdown conversion; a table lists the rows of its nested tables itself, so nesting depth never multiplies the output | ✅ |
| markdown_table.py | Util | Markdown table layout of converted table rows: the header and delimiter lines span the widest row and body rows keep their own cells, so one wide row among many short ones never multiplies the output (blank header when the table has none) | ✅ |
| markdown_generator.py | Util | Markdown document generation | ✅ |
| url_normalizer.py | Util | `normalize_url`: canonical URL used as the fetch cache key — known tracking parameters (`utm_*`, `fbclid`, ...) dropped but not generic names such as `ref` or `source`, which can select content; scheme and host lowercased, default port dropped, a plain anchor dropped while a hash route (`#/...`, `#!/...`) stays, repeated slashes collapsed, query sorted | ✅ |
| github_blob_url.py | Util | `github_blob_to_raw`: the `/raw/` URL of a github.com blob page (`/<owner>/<repo>/blob/<ref>/<path>`, query and fragment dropped), any other URL unchanged — another host, `www.`, a port or credentials, a path with an empty segment. The blob page wraps the file in a large HTML page that the HTTP tier cuts at its body ceiling; `/raw/` is the file, and GitHub resolves a branch name with slashes itself, so nothing here guesses where the ref ends. The engine applies it before the cache key (a blob link and a raw link share one entry); the redirect to `raw.githubusercontent.com` is judged by the fetch like any hop, so a blocklisted `raw.githubusercontent.com` still stops it | ✅ |
| full_content_delivery.py | Core | Delivery plan for full-content reads: one shared character budget split max-min fairly across pages, a truncation window per cut page, the exact saved-file line range of every omitted section, newline-normalized and soft-wrapped saved text, failed-URL listing; pages are labelled with the numbers the caller gives (`indices`: the run's source numbers, so a label is the index of the page's card), from 1 when none; `source_notice` names, by those numbers only (so it may sit outside the untrusted boundary), the pages whose source was cut, by the fetcher at its size ceiling or by the binary router at its parsed-text cap | ✅ |
| spill.py | Util | Saves the complete text through the injected evicted-content callbacks, builds the read guide and announces the saved file to the GUI | ✅ |
| html_scan.py | Util | Linear-time scans of raw HTML text (title, body, script/style blocks, tags) for pages that may be hostile | ✅ |
| antibot_detector.py | Util | `is_blocked(status_code, html)`: whether a crawl result is an anti-bot block or an error page, with the reason. Tier 1 WAF markers (any size), Tier 2 generic markers (pages under 10 KB), Tier 3 structure (no `<body>`, minimal text without content elements, or an untitled page of 3 or more scripts that shows under 200 characters: a WAF verification or loading screen). An HTML page served with 403 or any 5xx is blocked whatever its size; other 4xx (404, 410, ...) stay with the content rules, as they are the origin's final answer and L1 already stops on them. JSON/XML bodies are exempt from the status and structure rules. A blocked result makes the ladder degrade to the next tier | ✅ |
| charset_detector.py | Util | Tiered charset detection of a fetched body: header charset, `<meta>` charset, strict UTF-8, CJK trial decodes, then a replacement decode. `partial` marks a body cut at an arbitrary byte: its last half character is dropped, so the cut cannot fail the strict decodes or let a CJK trial decode read the page as mojibake. Needs only the standard library | ✅ |
| binary_router.py | Util | Binary content type routing (Content-Type, Content-Disposition, then `utils.content_sniff.magic_extension`); a body over `MAX_BINARY_SIZE` (20 MB, also the L1 transfer bound) is dropped, and a payload no parser accepts is rejected, never decoded as text; a parsed text over `MAX_PARSED_CHARS` (100,000 characters) is cut and its Document carries `SOURCE_TRUNCATED_KEY`, so the full-content tool names it in the size-limit notice | ✅ |
