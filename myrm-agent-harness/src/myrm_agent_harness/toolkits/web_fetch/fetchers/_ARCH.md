# fetchers/

## Overview
Toolkits Web_Fetch Fetchers module.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package |   Init   | — |
| bounded_get.py | Core | `bounded_get` — one GET through Scrapling whose body is held to `MAX_TRANSFER_BYTES` (the binary router's `MAX_BINARY_SIZE`, 20 MB) while it is received. Scrapling buffers and parses a whole response before any size check can run, so a compressed body that decodes to gigabytes, or a slow giant page, would cost memory and event-loop time in proportion to what the server sends. libcurl hands each decoded chunk to a sink that keeps the first `MAX_TRANSFER_BYTES + 1` bytes (the extra byte tells a file over the limit from one exactly at it) and ends the transfer by returning `CURL_WRITEFUNC_ERROR`; status and headers then come from the write error, which carries the response received so far. The request is attempted once; any other failure is raised. Given `addresses` (the ones the SSRF check looked at) it connects only to those, inside `pinned_connection`; a request through a proxy is not pinned, because the proxy resolves the host itself. Returns `FetchedResponse`. curl_cffi and Scrapling are imported when a request is made, so importing the engine needs neither. | ✅ |
| connection_pin.py | Core | `pinned_connection(url, addresses)` — inside it, the curl sessions the current task opens carry a libcurl `CURLOPT_RESOLVE` entry (`host:port:address,address`), so the connection goes only to the addresses the SSRF check looked at while the URL keeps the host name: the certificate is validated against the name (an IP-literal URL cannot be), the addresses are tried in turn, and the name is never resolved a second time. curl_cffi takes `curl_options` only when a session is created and Scrapling creates one per request, so the options travel in a context variable that a one-time wrapper of `AsyncSession.__init__` reads (one session per request, so concurrent fetches never share options). `ensure_connection_pinning` sends one real request, to an unresolvable `.invalid` name pinned to a loopback listener of the process, before the first pinned fetch and raises `ConnectionPinError` (an `SSRFSecurityError`, so terminal) when it does not arrive: a curl_cffi or Scrapling that stops honoring the pin cannot silently bring the check-then-connect gap back, and `tests/toolkits/web_fetch/test_connection_pin.py` asserts the same in CI. Not pinned: an IP-literal host, an address that cannot be written without its interface (link-local IPv6), and any request through a proxy (the pool's or the environment's). | ✅ |
| browser_fetcher.py | Core | Provides BrowserFetcher. A navigation the SSRF policy blocks raises `SSRFSecurityError` (never degrades to another tier); each fetch gets its own explicit-origin grants because pooled CRAWL contexts outlive it. The user's network blocklist judges the requested URL and the page the navigation ended on (`SSRFSecurityError`, never another tier); the hops between them are not visible to it, and the pooled contexts are shared by every user, so no list can be installed in them. | ✅ |
| http_fetcher.py | Core | L1 HTTP fetcher (Scrapling curl_cffi). SSRF defense through `FetchTargetGuard` on every hop (the requested URL and each redirect `Location`): a hop is judged and requested in its canonical spelling (`canonical_url`), so libcurl connects to the host the policy classified. The user's network blocklist is judged on the same hops, each before it is requested and whether or not the SSRF shield is on. The connection of each hop is limited to the addresses `FetchTargetGuard.pin` returned for it (`bounded_get`, `connection_pin`): the URL keeps the host name, so HTTPS checks the certificate against it, and a failed connection is never retried by name, which would resolve the host again, unchecked. A rejected hop (SSRF policy or blocklist) raises `SSRFSecurityError` instead of returning None, so the engine does not retry the same URL on a browser tier. Every body is received through `bounded_get` (no response holds more than `MAX_TRANSFER_BYTES + 1` bytes) and classified once by `utils.content_sniff.classify_payload` (declared type plus leading bytes): web pages and text are decoded into `html` and tagged `kind` WEB or TEXT, and only those bodies are cut at a ceiling: `MAX_HTML_BODY_BYTES` for a web page (its Markdown conversion is the costly step) and `MAX_PLAIN_TEXT_BODY_BYTES` for text (it follows what a stored copy of a page can hold). A cut body is decoded as `partial` (half a character at the cut is dropped instead of spoiling the charset choice) and the result carries `source_truncated`. A file stays whole as `raw_body` (`kind` BINARY) because a truncated PDF or Office file cannot be parsed; the transfer bound is the binary router's size limit, so a file over it arrives one byte over and the router drops it. | ✅ |
| target_guard.py | Core | `FetchTargetGuard` — per-fetch outbound policy shared by the HTTP and stealth tiers: the SSRF policy and the user's network blocklist (`assert_not_blocklisted`, a string match of the URL's host against exact and `*.` entries, the permission engine's matcher; a hit raises `NetworkBlocklistError`, an `SSRFSecurityError`, so it is terminal and is audited as a `web_fetch` DENY naming the host only). `for_fetch` returns no guard only when both are off. `canonical_url` is the spelling a hop is judged and dialed in (`utils/url_syntax.py`; a URL with none is refused with `SSRFSecurityError`); `pin` judges the blocklist first and then the SSRF policy, and returns the addresses the connection to that URL may use (empty when there is nothing to pin: the shield is off, the operator listed the host, the host is a literal address, or a local-policy lookup answered nothing). Cloud policy: DNS-resolved, every address public, and those are the addresses returned (`async_vetted_addresses`). Local policy (`allow_private_networks`): the URL is judged, granted and resolved in canonical spelling, and `pin` returns the addresses the verdict was reached on (`HopEvaluationResult.addresses`), through `RedirectHopEvaluator.evaluate_hop_resolved` (a hostname resolving to loopback, link-local or metadata is judged as that address), the requested origin may be private, any other private origin reached by redirect may not, cloud metadata never may; skill DLP allowlist and `MYRM_ALLOWED_INTERNAL_HOSTS` apply under both. | ✅ |
| protocols.py | Core | Provides FetcherType, FetchResult (with `kind: PayloadKind`, WEB by default and BINARY whenever `raw_body` is set, and `source_truncated` when the fetcher cut the body at its size ceiling), Fetcher protocol. | ✅ |
| stealth_fetcher.py | Core | Stealth Fetcher — Maximum anti-detection based on Scrapling Patchright + BrowserForge. DNS leak prevention via DoH when proxy is active. Ad/tracker domain blocking via Scrapling `block_ads`. Scrapling navigates without a route hook, so the requested URL is judged before the browser starts and the page it ended on before the body is returned, against the SSRF policy and the user's network blocklist alike (`SSRFSecurityError` otherwise); the hop between them cannot be vetted in flight. Under the strict network policy (no `allow_private_networks`, no proxy pool) the browser also connects only through an `EgressGuard` that lives exactly as long as the fetch (`create_egress_guard()`; None when the SSRF shield is off or the environment routes HTTP through a proxy): its proxy settings, `bypass` included, reach Scrapling's context through `additional_args` because Scrapling's own `proxy` option drops `bypass`, and Scrapling's `block_webrtc` flags forbid the UDP a proxy cannot carry, so a redirect hop, a subresource or a rebinding name that the two URL checks never saw still cannot reach an internal address. The guard stops on success, failure, timeout and cancellation alike. | ✅ |
